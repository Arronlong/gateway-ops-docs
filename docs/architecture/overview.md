# 系统架构

GatewayOps 采用 Go 后端、React 前端和 PostgreSQL。生产 Docker 镜像在构建阶段编译前端，再将静态资源嵌入 Go 服务；部署后由同一个 GatewayOps 服务提供 API 和页面。

## 组件

| 组件 | 职责 |
| --- | --- |
| React + TypeScript 前端 | 展示运营总览、管理页面、公开页面和交互状态。 |
| Go + Gin 后端 | 提供 API、连接外部服务、执行统计和业务规则。 |
| PostgreSQL | 持久化渠道、监控快照、通知、账本和中转站本地快照。 |
| 预警引擎 | 采集归一化指标、维护规则 / 事件状态、审计远端动作并关联通知；自动化当前仅适配 Sub2API。 |
| 后台调度器 | 执行余额监控、倍率监控、数据清理及已配置的周期任务。 |
| NewAPI / Sub2API 连接器 | 按站点类型访问渠道或 Sub2API 管理接口。 |
| 通知与 CAPTCHA Provider | 按配置连接外部通知服务和 Turnstile 解题服务。 |

## 部署结构

生产部署包含 GatewayOps 应用容器和 PostgreSQL 容器。浏览器访问 Go 服务，Go 服务访问 PostgreSQL 和已配置的上游 API；通知与 CAPTCHA 集成可能需要应用容器能访问公网。

前端不需要单独运行 Node.js 服务。Node.js 仅用于构建前端资源；运行时提供静态页面的是 GatewayOps Go 二进制。

## 安全边界

- 后台 API 可通过登录认证保护；认证是否启用由部署配置控制。
- 渠道凭据、通知密钥和中转站管理员 API Key 使用 `APP_SECRET` 加密后保存。
- 中转站管理 API Key 由后端使用，不应回传到浏览器。
- 公开监控、公开价格和公开状态路由无需后台登录，只应返回明确允许公开的数据。
- 数据库与应用之间通过 Compose 内部网络通信；默认数据库宿主机端口仅映射到回环地址。

## 数据责任边界

GatewayOps 保存上游快照和运营账本，但不取代 NewAPI / Sub2API 作为账号、分组、模型和用户用量的事实来源。统计报表是对远端数据、渠道余额快照和手工账目进行整合，读取失败或映射缺失会影响完整性。

## v1.1.2 的后台计算与请求出口

全渠道历史核对是独立服务端每日任务，按北京时间计划运行，接入执行历史与手动启动；页面单渠道回补仍使用原进度流，页面 30 秒刷新不再触发校对。

公开分组监控由后台采集、按日压缩入库，再生成四种固定区间安全快照，公开 API 仅读取投影。准备中不回退直查、失败保留旧快照，计算周期与浏览器读取周期分别控制。渠道代理记录全局加密复用，按渠道选择并隔离请求传输，不修改共享客户端。规则见 [同步与数据处理](/logic/synchronization)、[公开数据规则](/logic/public-monitor-and-pricing) 和 [渠道代理](/logic/channel-proxy)。
