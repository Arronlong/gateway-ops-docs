# 主要数据流

本页按运营流程说明数据如何进入页面。具体指标定义见 [指标口径](/logic/metrics)，计算公式见 [成本与倍率](/logic/cost-accounting)。

## 渠道监控

1. 渠道配置保存站点地址、凭据、账号模式和监控开关。
2. 后台任务或用户手动操作触发渠道连接器请求。
3. 后端读取余额、分组倍率及上游支持的调用日志。
4. 当前状态和历史采样写入 PostgreSQL；失败信息记录并可触发通知。
5. API 将当前快照、历史趋势和使用汇总返回前端。

余额采集与倍率采集有不同周期。页面展示“最近更新”时间，帮助判断当前看到的是新数据还是较旧的快照。

## 中转站快照和账号成本

1. 管理员 API Key 用于读取 Sub2API 管理接口。
2. 快照同步更新本地账号、销售分组、渠道和关联关系。
3. 成本倍率探测或覆盖规则提供账号成本来源。
4. 用量统计按账号读取远端扣费、请求和 Token 信息。
5. 后端按账号成本来源计算调用成本，并标记未知或读取失败的账号。
6. 风险规则将账号成本与当前销售分组倍率比较，生成状态和候选建议。

快照同步不会自动替代倍率探测；真实请求测试会额外产生上游调用和使用记录。

## 经营成本汇总

账本记录与渠道当前余额、Sub2API 用户扣费和账号调用成本分别汇总。前端将区间收入、支出、现金净额、当前余额、实际成本、用户消耗和差异并列展示。不同数据源保留各自口径，不把余额消耗与账号调用成本直接相加。

## 通知

余额任务、倍率任务或用户操作产生事件 → 订阅规则按渠道/分组筛选 → 冷却、合并或变化幅度规则处理 → 通知 Provider 投递 → 写入发送日志；失败时按配置重试。

通知重试只重试投递步骤。上游采集失败应通过下一次任务或人工同步重新获取数据。

## 公开页面

公开页面 API 从允许公开的本地监控记录或当前有效模型价格中生成只读视图。浏览器缓存和自动刷新降低重复读取，但公开监控状态仍来源于近期真实调用记录，不是当前时刻的可用性保证。
