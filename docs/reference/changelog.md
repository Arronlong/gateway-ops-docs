# 产品更新记录

本页依据主仓库 Git 标签、提交记录、可核验的发布说明和对应源码整理功能变化和升级影响。当前文档更新到 GatewayOps `v1.0.7` 标签提交 `82b4d07`；每个版本按其标签与实现记录，不以源码默认版本代替实际构建版本。

源码和 Dockerfile 未注入构建参数时的默认版本仍为 `1.0.1`；由 `v1.0.7` 标签触发的构建使用标签注入 `1.0.7`。开发版或自行编译版请以实例实际显示的提交号和构建信息为准。

## 2026 年 10 月 26 日：v1.0.7

对应标签提交：`82b4d076b9b3b8ce8cef143b58f1d7b9d6443e8b`。本次包含 `v1.0.6..v1.0.7` 的 3 个提交（含设计文档），依据 [GitHub Release](https://github.com/Arronlong/gateway-ops/releases/tag/v1.0.7)、[提交记录](https://github.com/Arronlong/gateway-ops/compare/v1.0.6...v1.0.7) 和标签源码整理。

### 全局品牌与产品名称

- 系统设置新增“品牌与产品名称”卡片，支持产品名称、图标上传及效果预览；点击“保存品牌设置”成功后应用，不是编辑即生效。
- 名称最多 40 个字符，不能包含控制字符；空名称回退 `GatewayOps`。原图支持 PNG、JPEG、WebP，最大 1 MiB，浏览器等比缩放并居中放入 128 × 128 PNG。
- 服务端独立验证 PNG 编码、内容、尺寸和体积：宽高各 1–128 像素，解码后最大 512 KiB；不接受任意远程图标 URL 或 SVG 上传。
- 顶部品牌栏、页面主标题图标、登录页、公开页面和浏览器标签使用统一品牌；标题格式为“页面名称 · 产品名称”。可恢复首页默认图标，读取或图片加载失败时回退默认显示。

操作与保存范围见 [系统设置](/guide/system-settings)，字段、校验和公开接口见 [配置项](/reference/configuration)。

### TPS 环形指标与独立排序

- 渠道及中转站账号新增 TPS，复用统计时长、最近数量与 45 秒截止偏移，从已选样本中筛选有效文字调用，以输出 Token 总数除以请求总耗时（秒）计算。
- 排除图片、进行中、辅助、探测及已确认的 cyber 调用，以及无效输出或耗时。零输出或省略零值仍保留有效耗时；没有有效样本显示不可用。
- 环形中心显示 Token/s，进度及“TPS 评分”排序使用 `min(100, TPS × 2)`；悬停可核对模型、统计范围、样本和计算过程。50 TPS 及以上同为 100 分，不是按原始速度继续拉开分值。
- TPS 不加入既有四项等权综合健康评分，不替代后台自动优先级，也不同于时间桶按单次输出速度计算的 P50 / P95。

完整公式、样本边界及示例见 [缓存指标与健康评分](/logic/cache-and-health-score)，不同速度指标的区别见 [延迟与稳定性](/logic/latency-and-stability)。

### 升级与兼容

未配置品牌时继续使用 `GatewayOps` 和默认 Activity 图标；旧数据库无需手工补品牌字段，也无需新增环境变量、业务表或文件存储服务。监控统计默认仍为 1 小时、60 条，修改品牌或指标设置后保存即可，不需要重启。镜像升级本身仍需按 [备份与升级](/deploy/security-backup-upgrade) 重新创建应用。

## 2026 年 10 月 26 日：v1.0.6

对应标签提交：`e78427d98af21008e6035edb85a007ddb5233b14`。本次包含 `v1.0.5..v1.0.6` 的 7 个提交，依据 [GitHub Release](https://github.com/Arronlong/gateway-ops/releases/tag/v1.0.6)、[提交记录](https://github.com/Arronlong/gateway-ops/compare/v1.0.5...v1.0.6) 和对应源码整理。

### 测智方案启停与配置

- 每项全局方案新增独立启用开关，保存后只有已启用且配置模型的方案进入自动执行及手动模型候选。旧方案缺少 `enabled` 字段时兼容为启用，禁用保留原参数。
- 方案配置收紧为两行布局；手动默认选择首个可用方案，直接调用 API 且不传单次方案时执行全部已启用的有效方案。没有可用方案时提示先配置并启用。
- 小时频率统一显示为“每 1 小时”，仍使用原 Cron 规则；全局任务开关、来源自动开关和自动时段继续生效，禁用方案不取消已开始的一轮。

操作见 [系统设置](/guide/system-settings)，启停层级及兼容规则见 [鹈鹕测智与作品历史](/logic/pelican-testing)。

### 生成中作品与原位更新

- 指定账号和分组在请求生成前先保存 `running` 结果，作品区可先看到“生成中”，完成或失败后更新同一条记录，不另建重复作品。
- 页面存在生成中结果时会在可见状态下定期查询进度；生成中记录不提供播放或删除入口。成功后可播放，失败后可查看原因。
- 保存结果时的常规历史清理跳过仍在运行的记录，短时记录数可能超过保留数；公开分组仍只展示最近成功作品。

### 监控统计时长与最近数量

- 统计时长改为下拉选择，仍允许 1–24 小时的整数，默认 1 小时，并保留已保存的非常用时长选项。
- 新增最近数量设置 `recent_metrics_limit`，默认 60、允许 1–200 的整数；影响渠道和中转站账号的最近调用、近期指标、综合评分、相关排序及两侧对比样本读取。
- 缓存命中率、重试感知成功率及综合评分同时受统计时长和最近数量限制；45 秒截止偏移、指标公式与四项权重保持原有规则。点击“保存监控设置”后生效。

样本选择与边界见 [缓存指标与健康评分](/logic/cache-and-health-score)，调用条带与时间桶见 [延迟与稳定性](/logic/latency-and-stability)。

### 导航与升级核对

导航栏“刷新视图”改为紧凑图标按钮，悬停可查看提示，仍用于刷新页面数据。升级后核对方案启用状态及监控参数；旧方案默认继续启用，未保存最近数量时使用 60。固定镜像与实例版本核对见 [版本与更新](/reference/versions)，升级步骤见 [备份与升级](/deploy/security-backup-upgrade)。

## 2026 年 10 月 26 日：v1.0.5

对应正式标签提交：`7f2b0b3f6523e186b07edb419fb7016b517373b0`。本次包含 `v1.0.4..v1.0.5` 的 9 个提交（含合并与文档），依据 [GitHub Release](https://github.com/Arronlong/gateway-ops/releases/tag/v1.0.5) 和标签源码整理。

### 预警中心、规则与对象筛选

- 统一预警事件、订阅规则、通知渠道和发送记录，提供 `/alerts` 入口并保留 `/notifications` 兼容入口。
- 区分渠道、中转站账号和用户，支持倍率变化、余额、成本 / 用户扣费、稳定性及用户多 IP 指标，按对象类型提供属性筛选和全部 / 任意匹配。
- 规则可预览范围并测试判定，支持窗口、最少请求、连续 / M 次命中、历史消耗基线和滞回恢复。未知、过期及不完整数据不算正常，也不自动恢复。

操作见 [预警中心](/guide/alerts)，公式、默认值、状态和采集节奏见 [预警判定与安全自动化](/logic/alerts-and-automation)。

### 安全自动化、通知与兼容

- 支持停止 / 恢复账号调度、停用 / 启用用户；停用动作可配置条件恢复。当前仅 Sub2API 支持远端自动化，New API 不支持的能力拒绝执行。
- 通过持久化动作占位、事件所有权、远端指纹、人工介入和多规则停用约束避免重复写入与误恢复；结果不确定的写请求不盲目重放。
- 预警规则复用已有通知渠道及内置消息，默认异常冷却 30 分钟，恢复通知独立处理，失败渠道后续重试；未选择通知渠道仍记录事件及动作。
- 修复关联通知渠道保存等待锁的问题。旧通知订阅、New API 管理、鹈鹕测智、定时任务历史及渠道 Token 刷新继续保留。

传统通知的空订阅与冷却不能套用到预警规则，见 [通知与验证码规则](/logic/notifications-and-captcha)。

### DeepSeek 官方状态

在 OpenAI、Claude 之后新增 DeepSeek 标签，展示官方当前状态、组件分组、60 天历史和事件。主摘要失败显示未知；历史与可用率缺失不补造正常值，DeepSeek 可用率取官方返回字段，不混用 OpenAI / Claude 的按天计算公式，见 [公开页面的数据规则](/logic/public-monitor-and-pricing)。

### 升级检查

1. 备份 PostgreSQL 与 `APP_SECRET`，核对正式 Release 和目标 `1.0.5` 镜像，按 [升级说明](/deploy/security-backup-upgrade) 重新创建应用。
2. 首次启动检查预警相关模型表结构同步，不把设计文档当成数据库迁移脚本。
3. 在开启真实远端自动化前检查对象范围、数字 ID、规则阈值及恢复条件，先以小范围仅通知规则观察。关闭事件不会恢复远端，暂停规则也不会继续自动恢复。
4. 预警总开关默认开启，规则按各自启用状态执行；频率设置通过受后台认证约束的 `/api/alerts/settings` 管理，当前无独立前端频率表单。

## v1.0.4（标签提交 `f6aa3ff`）

本节依据 `v1.0.3..v1.0.4` 的 7 个提交和标签源码整理；Git 标签、镜像发布与公开 Release 是不同状态，实际升级前请核对 [版本与更新](/reference/versions)。

### 鹈鹕测智方案与多来源作品

- 模型优先列表、题目、思考强度、运行频率统一移入系统设置，支持 1–8 项方案，每轮每项并行运行一次；账号 / 分组处只启停自动计划。
- 新增已保存时区、运行星期和有效时段，默认每天 `Asia/Shanghai` 的 `08:00`–`22:00`；支持跨午夜，手动测试不受自动时段限制。
- 区分页面展示和任务执行开关；作品保留数可设为 1–100，默认 30，调低立即清理，支持确认后手动删除作品。
- 渠道关联账号、远端 OAuth 号池账号、中转站分组可汇总到独立作品库，支持模型 / 思考强度和结果筛选；公开监控可只读查看公开分组最近成功作品。
- “测一次”可下拉选择本轮模型、题目及思考强度，不修改全局方案；未传单次参数的 API 调用仍使用全部已配置方案。
- 指定 Sub2API 账号改为读取模型目录和导出凭据后直连上游，不再要求旧 `pelican-test` 接口；分组走专用网关 Key。测智不执行登录、Token 续期或账号维护。

来源、费用、模型匹配、公开权限及删除副作用见 [鹈鹕测智与作品历史](/logic/pelican-testing)，操作入口见 [系统设置](/guide/system-settings)、[渠道管理](/guide/channels)、[本地号池](/guide/local-pool) 和 [中转站管理](/guide/relay-stations)。

### 任务执行记录与 Token 维护

- 定时任务新增 PostgreSQL 执行历史，记录运行 / 成功 / 失败、耗时、摘要和脱敏日志，支持分页查看；启动时会标记上次未结束任务为中断失败。
- 鹈鹕记录对象是定时调度检查，不能仅凭该记录成功就判断每份模型作品成功；功能上线前的执行不补历史。
- 新增独立 Sub2API 渠道 Token 定时刷新，默认关闭、30 分钟，只处理启用监控的 Token 模式凭据；失败按账号记录并继续其他账号。
- 迁回遗留测试并统一主分支验证，不增加用户必须启动的额外服务或配置项。

状态、日志截断及保留规则见 [定时任务执行历史](/logic/task-execution-history)，续期范围和凭据要求见 [同步与数据处理](/logic/synchronization)。

### 升级检查

1. 备份 PostgreSQL 与 `APP_SECRET`，确认目标 `1.0.4` 镜像和公开 Release 已完成发布后再拉取，按 [Docker Compose 部署](/deploy/docker-compose) 重新创建应用。
2. 启动会自动同步表结构；手动维护数据库时，对照标签下 `backend/migrations/0007_task_execution_history.sql`、`0008_pelican_key_group.sql` 和 `0009_group_pelican.sql`，不要重复执行已完成的迁移。
3. 在系统设置重新核对统一测智方案、任务开关、时区 / 时段、频率和保留数，不再依赖旧账号局部参数；降低保留数会删除历史，测智会产生真实调用费用。
4. 检查指定账号导出权限、分组专用 Key 与模型目录；不主动运行付费测试也可先核对配置。Token 定时维护需要另行开启并保存有效 Refresh Token。
5. 执行记录从升级后开始积累，不补造旧历史；主仓库中尚未进入 `v1.0.4` 标签的开发内容不属于本版说明。

## 2026 年 10 月 22 日：v1.0.3

对应正式标签提交：`15e7745`。本次发布包含 `v1.0.2..v1.0.3` 范围内的 11 个提交。完整内容见 [GitHub Release](https://github.com/Arronlong/gateway-ops/releases/tag/v1.0.3)；以下按发布说明与标签源码整理。

### 缓存指标与账号健康评分

- 渠道与 Sub2API 账号新增近期缓存命中率、重试感知成功率环形指标，并支持按缓存命中率和成功率排序。
- 缓存命中率改为按 Token 汇总加权；辅助调用、探测及已确认的 cyber 尝试不计入重试感知成功率。
- 系统设置新增 1–24 小时近期统计窗口，默认 1 小时，渠道和中转站账号共用；窗口保存后同步影响列表指标、排序及评分。
- 综合评分改为成功率、稳定性、缓存命中、延迟四项各 25%；任一项未知即不显示总分，不对剩余项重新加权，少于 10 次有效尝试标为低置信度。
- 修正缓存公式提示的百分比结果，补充监控指标独立保存入口，并修复列表标题未按配置显示统计时长的问题。

计算口径和边界见 [缓存指标与健康评分](/logic/cache-and-health-score)，设置入口见 [系统设置](/guide/system-settings)。

### 鹈鹕测智与作品画廊

- 新增 Sub2API 账号级 HTML / SVG 模型测智，可指定模型、题目、思考强度、并行份数和北京时间 Cron。
- 每账号默认关闭，可手动运行；画廊保留最近 30 份结果，支持交互预览、暂停、倍速和下载原始 HTML。
- 计划任务使用数据库租约防止同账号并行领取；New API 不支持该功能。
- 作品预览在受限 iframe 中运行，禁止访问外部资源和网络接口。
- 启动时自动同步测智所需表结构；也可按 [手动迁移文件](https://github.com/Arronlong/gateway-ops/blob/v1.0.3/backend/migrations/0006_account_pelican.sql) 执行。该功能要求上游支持账号级 `pelican-test` 接口，并会产生实际模型调用费用。

配置、费用、执行限制与作品安全见 [鹈鹕测智与作品历史](/logic/pelican-testing)。

### 升级检查

1. 备份数据库与 `APP_SECRET`，检查运行中的站点地址和管理员权限。
2. 当前 Compose 模板可设置 `GATEWAYOPS_IMAGE_TAG=1.0.3` 拉取固定版本；升级流程见 [Docker Compose 部署](/deploy/docker-compose)。
3. 确认 v1.0.3 容器启动完成并检查健康状态；启动时会自动同步测智表结构。
4. 鹈鹕测智默认关闭；启用前确认上游 Sub2API 支持账号级接口并了解调用费用。监控指标统计口径和综合评分已更新，与旧版数值不宜直接横向比较。

## 2026 年 10 月 21 日：v1.0.2

对应正式标签提交：`0e392e2`。本次发布包含 v1.0.1 之后的 10 个提交。

### New API 中转站管理

- 新增 New API 站点类型，可使用管理员用户名 / 密码、访问令牌或 Cookie + 用户 ID 接入。
- 同步 New API 渠道、分组、用户和用量日志，并将渠道适配为统一管理界面的账号。
- 支持管理已映射的调度 / 优先级、分组倍率、用户状态等操作，并执行分组真实调用测试。
- New API 与 Sub2API 的字段和权限并不等价：不支持并发、池重试、用户并发 / RPM 限额和 API Key 倍率探测；分组倍率修改需要相应全局权限。
- New API 报表补充完整分页、共享快照和短时缓存，改善使用记录及用户管理长时间读取不全的问题。

操作方式见 [中转站管理](/guide/relay-stations)，凭据安全、指标换算和能力限制见 [New API 中转站规则](/logic/newapi-relay)。

### 监控与界面优化

- 修复公开分组监控历史调用分页可能提前截断的问题；上游页数估算偏小时继续读取后续页面，超过安全上限则报错。
- 时间桶有请求但没有延迟字段时，改按成功率显示状态并提示“已有调用、上游未提供延迟”；空桶仍与缺字段区分。
- 优化 New API 管理页面布局、指标、权限提示、表单状态与图表交互。
- 顶部工具栏和小屏菜单新增文档站入口。
- 将“保存界面设置”按钮移到“界面与页面”标题行右侧。

数据口径见 [公开页面的数据规则](/logic/public-monitor-and-pricing) 和 [延迟与稳定性](/logic/latency-and-stability)。

### 升级检查

1. 备份数据库与 `APP_SECRET`，检查运行中的站点地址和管理员权限。
2. 当前 Compose 模板可设置 `GATEWAYOPS_IMAGE_TAG=1.0.2` 拉取固定版本。
3. 确认 v1.0.2 容器启动完成并检查健康状态；数据库会自动迁移中转站类型字段，旧站点保持 `sub2api`。
4. 如需 New API 管理，新增 NewAPI 站点并重新执行连接测试和快照同步。

## 2026 年 10 月 13 日：v1.0.0 之后的代码变更

### 调用对比与指标

对应提交：`4d5a704`（`feat(监控): 完善渠道与中转站调用对比`）。

- 渠道与中转站账号的近期调用支持双向关联对照，展示首字时间、总耗时和输出速度。
- 对照按当前账号关联选择候选，再以时间、模型、Token 数和相对位置配对；适用于辅助排查，完整匹配边界见 [渠道与中转站调用对比](/logic/call-comparison)。
- 时间桶增加输出速度 P50 / P95，调用明细增加交互及字段展示。速度与百分位计算见 [延迟与稳定性](/logic/latency-and-stability)。
- 调整搜索更新、浮层布局和明细展示，改善列表和指标查看体验。

使用入口见 [渠道管理](/guide/channels) 与 [中转站管理](/guide/relay-stations)。

### 版本检查与镜像发布

对应提交：`e668765`（`feat(版本发布): 接入版本查询与自动镜像发布`）。

- 增加运行版本接口和系统设置中的“版本与更新”，可查看版本、提交号、构建时间，并手动查询 GitHub 最新稳定 Release。
- 正式标签触发后端检查、`linux/amd64` 与 `linux/arm64` 镜像构建及 GitHub Release 发布；最高稳定版本推进 `latest`，预发布和开发构建使用各自标签。
- 默认发布 GHCR，Docker Hub 保持可选。未配置完整 Docker Hub 凭据时跳过该目标；仅使用 GHCR 无需配置 Docker Hub。
- 当前 Compose 镜像默认指向 `ghcr.io/arronlong/gateway-ops`，可通过 `GATEWAYOPS_IMAGE_TAG` 选择 `latest` 或固定版本。

接口状态、缓存及标签规则见 [版本与更新](/reference/versions)，运行镜像的操作见 [Docker Compose 部署](/deploy/docker-compose)。

### 升级时检查

1. 核对目标版本的正式 Release 与镜像标签，备份数据库和 `APP_SECRET`。
2. 使用旧 Compose 文件时，确认 `app.image` 已指向目标 GHCR 地址；使用当前模板只需设置镜像标签。
3. 重新创建应用后，在系统设置确认版本、提交号和构建时间；点击“检查更新”本身不会替换容器。
4. 同步渠道和中转站，抽查账号关联、近期调用、速度百分位与明细；缺失上游字段不会因升级自动补齐。
