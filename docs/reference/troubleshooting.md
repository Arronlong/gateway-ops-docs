# 常见问题

## `docker compose up` 提示环境文件不存在

当前 Compose 配置引用 `.outbound-proxy.env`。如果不使用该文件中的代理设置，请创建空文件，或按本机部署需求移除对应的 `env_file` 配置。检查 `.env` 是否存在，并确认 `GATEWAYOPS_DATABASE_PASSWORD`、`APP_SECRET` 已设置。

## 应用无法连接 Sub2API

确认 Base URL、管理员 API Key 和容器网络可达。当前 Compose 默认依赖 `sub2api-deploy_sub2api-network` 外部网络；网络不存在时创建它，或修改 Compose 网络声明。跨主机部署需使用应用容器可访问的真实地址。

## 公网打开后没有登录页面

检查 `AUTH_ENABLED` 是否为 `true`，并确认 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 已配置。认证关闭时，后台页面不会要求登录；不要将这种模式直接暴露到公网。

## 渠道同步或登录测试失败

检查站点地址、认证模式、凭据、代理和最近错误日志。启用 Turnstile 的站点还需绑定已测试通过的 CAPTCHA Provider。确认服务器时间正常，Token 未过期，并核对上游 API 是否发生变化。

## 公开模型价格缺少模型或价格

在 Sub2API 后台为每个销售分组创建并启用分组 API Key，再回到 GatewayOps 执行实时同步。分组 API Key 与中转站管理员 API Key 不同。

## 成本显示不完整或倍率为空

查看完整性标记、失败账号数和未知成本账号数；检查账号成本来源、渠道分组覆盖、账号与渠道映射以及读取窗口。实时倍率要求用户扣费分母为正值；没有扣费时为空是预期行为。

## 首页和渠道页的消耗不一致

核对是否有手工余额渠道。当前首页会对手工余额渠道使用关联账号调用成本，而渠道页使用渠道余额消耗汇总；两者可能不一致。进一步查看 [指标口径](/logic/metrics)。

## 延迟或成功率没有数据

检查所选窗口内是否有调用样本、上游是否提供相应字段、请求结果是否已知以及数据是否已同步。空值代表缺少有效样本，不应当作 0 ms 或 0% 成功率。

## 通知没有送达

先测试通知渠道，再检查事件订阅、渠道/分组过滤、倍率变化阈值、低余额冷却和失败重试日志。测试消息成功不代表该事件已被订阅。

## 恢复后凭据无法解密

恢复数据库时必须使用与备份对应的 `APP_SECRET`。更换主密钥不会自动重新加密已有密文。



## 关闭渠道自动同步后仍看到后台请求

确认页面同步设置是否已经保存。未配置时仍使用启动的余额 / 倍率 cron；保存后才切换为页面完整同步模式。另外检查是否存在手动同步或中转站独立任务。见 [同步与数据处理](/logic/synchronization)。

## New API 连接、分组倍率或调用日志读取失败

确认站点类型选择为 NewAPI、地址使用 HTTPS（仅本机回环允许 HTTP），管理员凭据与用户 ID 对应且具有所需权限。密码方式遇到二次验证时改用已完成验证的访问令牌或 Cookie。修改分组倍率需全局设置权限；真实分组测试需管理员名下匹配目标分组的令牌。成本探测、并发与池重试字段不属于 New API 支持范围，详见 [New API 中转站规则](/logic/newapi-relay)。

## New API 历史用量不完整或页面读取时间较长

New API 使用记录需读取多个原生分页，初次生成报表可能较慢；短时重复查询会复用约 1 分钟缓存。检查管理员日志读取权限、时间窗口与筛选条件。上游延迟字段缺失时，调用数仍可能存在，时间桶按成功率显示状态，不能因此判断没有请求。

## 缓存命中率或重试感知成功率为空

检查系统设置中的“监控指标”统计时长、最近数量与实际样本数，以及上游缓存 Token / 尝试结果字段。两项设置需保存，默认 1 小时、60 条，数量可设为 1–200；统计还排除当前时刻最近 45 秒的记录，调大时长不保证有足够样本。缓存率要求窗口内存在有效 Token 总量；成功率排除辅助、探测和已确认的 cyber 调用，只统计有结果的有效尝试。窗口内虽有请求但缺少对应字段时，指标可能未知，详见 [缓存指标与健康评分](/logic/cache-and-health-score)。

## 综合评分显示 `--` 或低置信度

综合评分要求成功率、稳定性、缓存命中和延迟四项均有可计算数据；任一项缺失则不输出总分。少于 10 次有效尝试时会标记低置信度。检查已保存的统计时长、最近数量、有效尝试数和上游字段，不要把 `--` 当作 0 分。

## 鹈鹕测智无法启动或没有作品

先判断是否为 v1.1.0 的纯渠道直连：该路径只需要已配置的渠道 Key、正确站点地址和具体模型，不需要中转站关联。已关联路径中，Sub2API 账号凭据直连需要 OpenAI 协议账号、目录和管理员导出权限；NewAPI 使用渠道 Key，不支持账号凭据导出直连；分组路径仍需目标组专用调用 Key。旧 `pelican-test` 接口不再需要，也不会借用其他账号或分组凭据。

检查全局任务开关、方案启用状态、模型优先列表、有效题目和模型支持；至少要有一项已启用且配置模型的方案，手动参数也不能绕过禁用；自动生成还要求来源开关已开启，并在已保存时区的星期 / 时段内。NewAPI 还要确认从关联渠道发起且已配置渠道测智 Key；Sub2API 可检查渠道 Key 或账号导出凭据与管理员导出权限。页面隐藏不暂停任务；手动参数不会修改全局方案。账号 Token 过期需走维护，不会由测智续期。超过 10 分钟或输出不完整会失败，详见 [鹈鹕测智与作品历史](/logic/pelican-testing)。

## 作品一直显示“生成中”

`running` 表示结果已创建，尚未完成输出与校验，不是成功作品。可见页面约每 5 秒查询进度；确认请求及任务日志是否继续更新，再检查上游超时或应用是否重启。不要反复点击测一次来刷新状态，重复生成可能产生新调用费用。生成中不提供播放或删除入口，关闭方案也不取消已开始的一轮。

## 作品变少、删除后又出现新结果

卡片通常只展示最近 3 份，完整历史到作品库查看。保存完成结果时的常规清理跳过仍在运行的记录，因此短时数量可能超过保留数。保留数按账号 / 分组计算，默认 30、可设置 1–100；调低立即删除旧结果，增大不能恢复。手动删除的是底层结果，多处引用会同时消失，但不会停止后续自动生成；公开页面仅展示最近成功作品。

## 定时任务没有记录或日志未更新

执行历史不补造上线前记录，不保证包含手动业务操作或因重叠跳过的轮次。日志通常在结束时写回；打开记录约每 5 秒刷新。先检查启用状态、触发时间及数据库写入，服务重启会把未结束记录标为中断失败。鹈鹕调度检查成功也可能没有到期对象，作品结果需另查，见 [定时任务执行历史](/logic/task-execution-history)。

## 渠道 Token 定时刷新失败

确认开启了渠道 Token 刷新任务和渠道监控，凭据是 Sub2API Token 模式并保存有效 Refresh Token。缺少 / 失效的 Refresh Token 不会通过密码登录或测智自动修复；New API 和密码模式不参与此任务。查看账号凭据错误与 `channel_token_refresh` 执行详情，部分账号成功不代表全部续期完成。

## 自动调组没有动作或关闭后没有恢复

检查账号是否启用、成本有效、模型已绑定，是否存在可应用建议，以及亏损 / 无利润开关。自动调组由快照或倍率同步触发，单账号探测和页面刷新不直接触发。自动关闭调度没有自动恢复步骤，修正后还需核对可调度状态。见 [自动调组](/logic/auto-group-adjustment)。

## 手工优先级被改回，召回速度与等待时间不一致

开启自动优先级后，快照同步会覆盖手工值。召回等待时间决定是否进入召回，进入后每轮快照降低一级数字，不是每等一轮等待时间才变化。见 [自动优先级与召回](/logic/auto-priority)。

## 改了成本倍率，历史汇总与趋势对不上

区间调用成本可按当前有效覆盖倍率重算，消费趋势使用逐条远端历史成本字段；两者不保证相等。再检查未知 / 失败数与缓存。见 [成本与倍率](/logic/cost-accounting) 和 [指标口径](/logic/metrics)。

## 隐藏模块后任务仍在运行，或 iframe 被拒绝

页面显示开关不是后台任务开关；停止采集需修改同步或监控设置。iframe 白名单用主机模式，不包含协议与路径，还需确认 Referer 和代理响应头。见 [访问与显示策略](/logic/security-and-access)。

## `.env` 配了代理或通知策略但没生效

先检查 Compose 是否显式透传。项目 `.env` 主要用于插值，额外参数需加入 `environment` 或 `env_file`；代理需映射标准 `HTTP_PROXY / HTTPS_PROXY / NO_PROXY`。修改启动参数后重新创建应用。见 [部署配置](/deploy/configuration)。

## 关联调用对不上，或两侧时间桶不同

检查关联是否命中正确的渠道凭据账号与中转站账号，两侧是否完成同步，以及时间范围、粒度和字段是否一致。近期调用在没有模型 / Token 候选时按相对位置回退；时间桶也可能使用最近开始时间，因此有对照数据不保证是同一次请求或完全相同窗口。详见 [渠道与中转站调用对比](/logic/call-comparison)。

## 桶请求数大于明细条数，或输出速度为空

后台明细默认最多展示桶内最近 30 条，桶统计请求数可能更多。速度要求输出 Token 和总耗时均为有效正值；上游没有提供这些字段时为空。输出速度 P95 表示偏快的一侧，耗时 P95 表示偏慢的一侧，见 [延迟与稳定性](/logic/latency-and-stability)。

## 检查更新失败、没有 Release，或版本信息为 unknown

`check_failed` 表示查询或版本解析失败，接口返回 HTTP 502；`no_release` 表示 GitHub 没有可用稳定 Release。这两种情况都不能视为已是最新版。结果存在缓存，检查网络、限流和实际 Release 后再重试。本地构建未注入提交号与时间时显示 `unknown`，查看 [版本与更新](/reference/versions)。

## 拉取 latest 后，应用版本没有变化

检查 `.env` 中的 `GATEWAYOPS_IMAGE_TAG` 是否为 `latest`，以及当前容器实际使用的镜像标签。固定标签的容器不会因为拉取另一个 `latest` 标签就自动更新；按目标标签运行 `docker compose pull app`，再用 `docker compose up -d --no-build app` 重新创建应用。检查更新按钮只查询版本信息，完整步骤见 [安全、升级与备份](/deploy/security-backup-upgrade)。

## 预警没有触发、未通知或未自动恢复

先检查规则及总开关、对象类型 / 站点 / ID / 属性范围，再看新样本、同步覆盖、最少请求和触发次数。余额默认 5 分钟一份样本，连续 3 次不是等 3 分钟。未勾选规则通知渠道不会发送，渠道测试成功也不代表规则已经命中。

恢复需本事件成功停用且状态指纹未变、没有人工介入或其他规则停用约束；暂停规则不继续自动恢复，关闭事件不等于启用远端。New API 不支持的远端自动化拒绝执行；不确定写入不要反复重试，先核对动作审计。详见 [预警中心](/guide/alerts) 和 [判定规则](/logic/alerts-and-automation)。

## DeepSeek 状态历史为空或可用率未显示

检查官方摘要、结构历史及事件列表是否完整。组件上线前的日期为未知，官方没有提供的可用率不补造。当前状态可读但历史不完整时可以同时显示当前状态和历史缺失提示；官方正常不证明实例代理或出口正常，见 [公开页面的数据规则](/logic/public-monitor-and-pricing)。

## 品牌修改后没有生效或图标上传失败

编辑只改变卡片草稿，先确认点击“保存品牌设置”且保存成功；其他已经打开的页面可刷新重新读取。名称最多 40 个字符且不能含控制字符，空白名称会使用默认值。原图须为 PNG、JPEG、WebP、大小 1 字节–1 MiB；浏览器转换为 PNG，服务端还检查宽高不超过 128 像素、解码体积不超过 512 KiB 及内容完整性。恢复默认图标也需保存，不会同时重置名称。公开品牌接口失败或图标加载失败时默认显示不等于配置被删除，详见 [配置项](/reference/configuration)。

## TPS 不可用、为零或排序看不出速度差异

先核对已保存的统计时长、最近数量、45 秒截止偏移及上游输出 / 耗时字段。图片、进行中、辅助、探测和已确认的 cyber 调用不参与，筛选后不会额外补齐更早样本。没有有效耗时显示不可用；有效耗时下的零输出是 0 TPS，不能忽略其耗时。TPS 评分从 50 TPS 起封顶 100，同为 100 分并不表示真实速度相同；它是独立排序，不影响综合健康分或自动优先级。公式及混合模型边界见 [缓存指标与健康评分](/logic/cache-and-health-score)。

## 公开分组两处成功率不同，或三项近期指标不可用

首行成功率使用页面历史范围的最终请求结果，近期环形成功率使用系统设置的统计窗口与最近数量，并保留重试前的有效失败。先核对两处范围，不直接将差异判定为错误；公开调用明细最多 60 条，不是环形指标的计算输入。

近期指标默认 1 小时、60 条，截止当前取数时刻前 45 秒。检查用量与错误记录的管理员读取权限、分页错误、Token / 耗时字段和更新时间；任一数据源不完整会使三项不可用，没有有效样本也不会显示 100%。

升级后刷新公开页，确认前后端版本一致及响应带有 `recent_metrics`；新浏览器缓存为第 3 版，不复用旧版缓存。修改监控采样需保存并等页面刷新，不能靠切换历史范围修改近期窗口。错误记录支持数字或字符串 `request_type`，若仍报解析错误应检查原始字段格式，详见 [公开页面的数据规则](/logic/public-monitor-and-pricing)。

## 渠道测智密钥未生效或 NewAPI 测智失败

编辑渠道时，Key 留空是保持原值；使用“清除”并保存才会删除。保存后检查渠道响应中的 `pelican_key_configured`，该接口不会回显密钥。未关联中转站时，NewAPI / Sub2API 均需渠道 Key，使用纯渠道手动直连；有账号关联时，NewAPI 需要从对应渠道启动并配置有效上游 Key，Sub2API 留空才检查管理员导出权限、模型目录及账号凭据。若一个中转站账号关联多个渠道且 Key 不同，从目标渠道卡片发起，避免使用无渠道上下文的账号入口。

纯渠道直连需确认启用方案模型列表首项是具体模型名，不能用 `*`，并检查渠道站点地址的 Chat Completions 能力；不必为此先创建中转站。已关联路径则检查目标账号映射、模型目录与上游 Base URL。渠道 Key 不等同于 NewAPI 管理凭据、Sub2API 管理 API Key 或分组网关 Key。

## 渠道自定义 Header 导致认证失败

核对 Header 模板是否与认证方式匹配：`cookie` / `user_id` 适用于 NewAPI 会话，`token` / `access_token` 需会话令牌已取得；未解析的会话 Header 会被跳过。自定义同名项会覆盖自动生成的 `Authorization`、`Cookie` 或 `New-Api-User`，可先恢复默认 Header 后重试登录 / 同步。不要在 Header 列表放长期有效密钥，详见 [渠道管理](/guide/channels)。

## 未关联渠道找不到“测一次”或显示具体模型错误

确认已升级到 v1.1.0 且前后端一致，渠道 Key 已保存并显示已配置，全局任务和目标方案均已启用。没有账号目标但有 Key 时，渠道卡片与作品库渠道区提供直连按钮；没有 Key 时仍可能提示先关联账号。

“直连测智需要配置具体模型”说明方案模型列表为空，或首项包含 `*`；改为实际可调用的模型名再保存，不会通过远端目录自动展开。渠道站点地址需提供 OpenAI 兼容 Chat Completions 服务，登录密码、Cookie 和自定义 Header 不替代直连 Key。

纯渠道直连只支持手动测试，显示定时关闭不影响手动入口。不要通过重复点击查询进度，新的请求可能增加调用费用。查看旧直连作品时可将中转站筛选切回全部；它们属于渠道，不属于某个中转站。

## 没有测智作品时渠道页面崩溃

v1.1.0 已修复空作品引发的筛选崩溃：后端使用 `results: []`，前端也兼容旧响应中的 `null`。升级后刷新页面，空列表应正常显示；若仍崩溃，核对前端静态资源与后端版本是否一致，再检查实际请求错误。
