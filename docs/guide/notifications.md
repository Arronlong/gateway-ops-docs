# 通知与验证码

## 通知渠道

GatewayOps 支持 Telegram、Webhook、SMTP 邮件、企业微信、钉钉、飞书和 Bark。每个通知渠道分别维护连接凭据、启用状态和测试结果；测试成功只说明当前投递链路可用，不代表所有事件都已订阅。

## 订阅事件

可订阅的事件包括余额不足、倍率变化、登录失败、验证码失败和监控失败。订阅规则可按渠道或分组过滤。倍率变化支持最小变化幅度过滤；同一轮扫描中的倍率变化可合并发送；低余额事件支持冷却时间；投递失败可配置重试次数。

当前示例默认把倍率变化批量合并、低余额通知冷却 60 分钟、发送最多尝试 3 次，重试间隔逐步增加且有上限。生产环境的实际设置可能不同，以部署配置和系统设置为准。

## Turnstile 验证码服务

在验证码服务中添加 CapSolver、2Captcha、Anti-Captcha 或 YesCaptcha 等 Provider，先执行测试，再将可用 Provider 绑定到相应渠道。该能力用于处理启用了 Cloudflare Turnstile 的登录流程，不替代站点本身的认证。

如果验证码失败，检查 Provider 凭据、余额、任务类型、代理连通性和站点是否启用了 Turnstile。通知中的验证码失败和登录失败是不同事件，应分别检查。
