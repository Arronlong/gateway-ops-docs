# 渠道管理

渠道记录上游站点地址、认证方式及余额 / 倍率 / 使用数据。自动余额通过连接器采集，手工余额由运营登记，两种模式有不同处理规则。

## 添加与验证

1. 选择站点类型，填写站点地址、Base URL 及支持的认证方式。
2. 按需添加多个凭据账号；各账号单独维护认证和最近错误。
3. 密码登录需要 Turnstile 时，先配置并绑定验证码服务。
4. 执行登录测试，再运行完整同步，检查余额、分组倍率和支持的使用日志。
5. 设置监控开关与低余额阈值，最后配置全局同步任务。

Token 模式直接校验提供的凭据，不执行普通密码登录；支持的 Sub2API Refresh Token 失效刷新与普通账号会话复用不同。密码模式可复用有效会话，校验失败后重新登录。保存配置本身不代表上游认证已通过。

Sub2API Token 模式还可在系统设置开启独立的“渠道 Token 刷新”维护任务，默认关闭、30 分钟；只处理启用监控且保存了 Refresh Token 的凭据账号，不处理密码模式。续期范围与失败排查见 [同步与数据处理](/logic/synchronization)。

## 渠道测智 API Key 与认证 Headers

渠道编辑表单中的“测智 API Key”独立于渠道登录凭据，用于渠道测智。v1.1.0 起，未关联中转站账号但已保存 Key 的渠道也可手动直连站点地址测试；已关联账号则继续使用对应账号路径。NewAPI 渠道测智需要 Key，Sub2API 未配置时仍可通过关联账号导出凭据直连。

编辑时密钥不会回显：留空表示保持原值，填写新值会替换，使用“清除”开关并保存才会删除。密钥最多 4096 字节，由 `APP_SECRET` 加密保存，渠道接口只返回 `pelican_key_configured` 状态。更换或清除密钥不会同步修改关联账号凭据，也不影响分组测智所用的分组网关 Key。

“Headers”配置统一用于 NewAPI / Sub2API 的登录、认证、Token 刷新和后续渠道请求。除用户名、密码和验证码外，还可用会话变量构造认证头：

| 模板 | 可用值 |
| --- | --- |
| `{{username}}`、`{{password}}` | 当前渠道凭据账号的用户名、密码。 |
| `{{turnstile_token}}` | 当前登录测试取得的 Turnstile Token；为空时，依赖它的 Header 不发送。 |
| `{{cookie}}`、`{{user_id}}` | NewAPI 会话 Cookie 与 User ID。 |
| `{{token}}`、`{{access_token}}` | 当前会话访问令牌；Sub2API 使用 Access Token，NewAPI 访问令牌模式也提供这两个别名。 |

依赖尚未生成的 Cookie、User ID 或 Token 的 Header 会跳过，不发送未替换的占位符。自定义同名 Header 会覆盖连接器自动生成的认证值。Header 配置值随有权限读取渠道设置的请求返回，不要在其中写入长期有效的明文密钥；需要保存秘密时使用加密凭据字段。

自定义认证失败时检查占位符是否与当前认证模式匹配、Header 名称是否正确，以及自定义值是否覆盖了默认 `Authorization`、`Cookie` 或 `New-Api-User`。登录和 Token 刷新问题见 [排错指南](/reference/troubleshooting)。

## 未关联中转站时手动测智

1. 在新增 / 编辑渠道中保存“测智 API Key”，确认站点地址能提供 OpenAI 兼容 Chat Completions 服务。
2. 在系统设置启用测智任务和至少一项有效方案；模型列表首项填写可调用的具体模型名，不使用 `*`。
3. 在渠道卡片或作品库的对应渠道区点击“测一次”；下拉可临时选择本轮方案、题目与思考强度。
4. 查看“生成中”记录，完成后预览作品或查看失败原因；完整历史仍在作品库渠道区。

直连模式只提供手动测试，不会因保存 Key 自动建立定时任务。全局模型方案仍校验，但不会查询中转站模型目录；如模型列表有多项，只使用首项，不在失败后轮换。已关联账号时页面沿用账号操作，更多区别见 [测智规则](/logic/pelican-testing)。

## 余额模式与多账号

自动模式读取上游；多账号余额按已知值汇总，失败账号可能暂用上次余额并保留错误。合计有数值不表示全部账号采集成功，必须一起看更新时间和失败明细。

手工模式不读取上游余额 / 倍率 / 使用日志，普通同步不自动扣掉中转站调用成本；可通过手工余额与关联充值账本维护。切换模式后检查余额及关联配置。详见 [渠道余额与调用记录](/logic/channel-consumption)。

## 监控与同步

暂停监控会让自动扫描跳过该渠道；手动完整同步可包含暂停渠道。渠道完整同步依次尝试余额、倍率与调用日志，各阶段可能部分失败。

全局同步存在“未保存时使用启动 cron”和“已保存时使用页面完整同步任务”两种模式。关闭已保存的自动同步不会恢复旧 cron，见 [同步与数据处理](/logic/synchronization)。

## 指标与分组

低余额只有在阈值大于 0 且余额严格低于阈值时触发。倍率变化来自连续采样对比，不是对所有上游调价的完整记录；部分同步失败可能保留旧分组。

首字时间、成功率、输出速度和稳定性依赖连接器提供的字段；未知结果不应当作失败，空延迟不应当作 0 ms。调用记录首次约回填 30 天，后续重叠读取并去重，见 [延迟与稳定性](/logic/latency-and-stability)。

渠道自身调用日志与映射的中转站用量是不同来源。账号映射不唯一或覆盖失效时，先修正关联再对账；详细口径见 [指标口径](/logic/metrics) 与 [成本与倍率](/logic/cost-accounting)。

## 查看关联调用与明细

确认渠道凭据账号已关联中转站账号后，悬停“最近调用”中的记录，可并排查看两侧首字时间、总耗时和 Token 速度。悬停“时间稳定性”的非空桶，可查看延迟与输出速度 P50 / P95，并对照关联账号的桶数据。

点击记录或时间桶打开明细；近期记录有对应桶时展示桶内最近 30 条，没有对应桶时只展示该记录。桶请求数可以大于明细条数。关联结果不保证是同一请求，匹配条件与时间桶对齐见 [渠道与中转站调用对比](/logic/call-comparison)。

列表还展示近期缓存命中率、重试感知成功率、TPS 环形指标和综合评分，可按缓存命中率、成功率或 TPS 评分排序。TPS 中心显示 Token/s，进度与独立排序使用 `min(100, TPS × 2)`，不会改变综合健康权重。统计时长和最近数量由系统设置的“监控指标”区统一控制，默认 1 小时、60 条，数量可设为 1–200，查看口径见 [缓存指标与健康评分](/logic/cache-and-health-score)。

## 鹈鹕作品

渠道卡片展示已关联中转站账号的最近 3 份作品，点击测智入口前往 `/pelican` 的该渠道作品组。可查看模型、思考强度、生成中 / 成功 / 失败及可获得的上游 Key 分组 / 倍率；“测一次”下拉可选择本轮模型并临时修改题目和思考强度。定时方案在系统设置统一维护，只有已启用方案进入新执行与手动候选。v1.0.9 起渠道可配置独立测智 Key：NewAPI 关联账号需要该 Key，Sub2API 则优先使用它，留空继续走原账号凭据直连。生成前先显示“生成中”，结束后同一记录更新；作品生成不复用渠道密码登录请求。

未关联账号时，有渠道测智 Key 可直接手动测试；没有 Key 时需先配置 Key，或建立关联后使用支持的账号路径。隐藏作品区不会暂停既有任务。全局作品库、费用、删除和来源规则见 [鹈鹕测智与作品历史](/logic/pelican-testing)。

系统设置可以隐藏卡片，但不会停止后台采集。删除渠道前确认历史、凭据及关联是否仍需保留。

## 渠道预警

v1.0.5 可在 [预警中心](/guide/alerts) 为渠道设置余额低或模型倍率变化规则，并按模型、类型、监控状态等属性筛选。渠道规则只记录和通知，不自动改变中转站账号调度；规则判定与传统余额通知不同。
