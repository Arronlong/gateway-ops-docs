# 预警中心

v1.0.5 新增预警中心，统一管理规则触发、远端自动化、消息通知和执行记录。入口为 `/alerts`，旧 `/notifications` 入口继续可用；验证码仍是独立配置，不参与预警判定。

## 页面与指标

| 区域 | 用途与口径 |
| --- | --- |
| 待处理事件 | 尚未恢复的事件数，不等于失败请求数。确认已查看不会减少该数。 |
| 运行中规则 | 已启用的规则数，不表示每条规则都有有效样本。 |
| 通知渠道 | 已启用的通知渠道数。 |
| 自动化处置 | 按 `Asia/Shanghai` 自然日统计的成功动作记录数；不是对象去重数，也不取浏览器时区。 |
| 预警事件 | 查看异常值、判定摘要、恢复情况、动作与通知结果。 |
| 订阅规则 | 新建、编辑、启停、测试规则；测试不执行远端状态变更。 |
| 通知渠道 / 发送记录 | 复用已有投递配置，核对各渠道实际发送结果。 |

## 创建一条规则

1. 点击“新建规则”，先选择渠道、中转站账号或中转站用户，再指定指标。切换对象类型会重置不兼容的指标、动作及筛选条件。
2. 选择站点、对象 ID 和属性过滤条件。渠道使用 GatewayOps 本地渠道 ID；指定中转站账号或用户 ID 时，只能选择一个站点，避免跨站同号对象混淆。
3. 配置统计窗口、阈值、最少请求数、触发次数及恢复条件。可选连续命中或最近 M 次中命中 N 次；余额恢复阈值须高于触发值，其他指标须低于触发值。
4. 先使用范围预览或规则测试核对命中对象、实际值及未知原因。范围预览显示匹配总数，样例最多 10 个；试运行只验证当前条件，不累计连续命中证据，也不执行远端启停。
5. 选择仅记录与通知，或对应的一个远端动作。渠道规则只能记录与通知；远端自动化当前仅适配 Sub2API。
6. 勾选现有通知渠道、设置冷却并确认启用。没有勾选渠道时仍记录事件及动作结果，不表示自动向所有渠道发送。

建议先使用小范围、仅通知的规则核对数据和阈值，再启用自动化。规则保存不会立即完成采样、触发和恢复；实际延迟受采集频率与新样本数量影响。

## 对象属性筛选

支持“全部匹配”或“任意匹配”，最多 20 条属性条件。文本支持相等、不等、包含和不包含；数值支持大小比较；布尔值使用 `true` / `false`；时间使用带时区的 RFC3339 值。缺失属性不会自动视为命中。

| 对象 | 可选属性 |
| --- | --- |
| 渠道 | 名称、类型、监控状态、余额模式、余额、运行评分、缓存命中率、模型。 |
| 中转站账号 | 站点类型与名称、账号名称与标识、平台、账号类型、状态、调度状态、套餐、模型类型、过期与最近使用时间。 |
| 中转站用户 | 站点类型与名称、用户名、邮箱、角色、状态、余额、并发上限、每分钟请求上限、最近使用与创建时间。 |

属性过滤决定监控范围，不等于触发阈值。自动化必须使用远端数字 ID，不能把邮箱当成可写目标；完整指标与边界见 [预警判定与安全自动化](/logic/alerts-and-automation)。

## 处理事件与恢复

- “确认”仅标记已查看，不停止通知、关闭事件或恢复远端。
- “关闭”结束事件但保留远端状态，不等于启用账号或用户。
- 停止调度 / 停用用户可选择条件恢复后自动恢复，也可不自动恢复；启用动作不会反向自动停用。
- 暂停规则会停止该规则的评估和自动恢复；已有停用对象需要人工关注。存在未恢复事件时不能删除规则。
- 有活动事件时，仅能修改名称、通知渠道、冷却、备注和启用状态；修改判定、范围、动作前先处理活动事件。

自动恢复只允许恢复由本事件成功停用且仍可确认所有权的对象。人工介入、远端状态版本变化、其他规则的停用约束或结果不确定，都可能阻止恢复；应以事件动作记录为准，不能只看条件已正常。

## 通知与排查

消息内容内置，默认异常通知冷却 30 分钟，按事件与通知渠道分别计算。恢复通知独立发送；失败渠道后续重试，成功渠道不因其他渠道失败而重复发送。旧通知订阅与预警规则使用不同筛选入口，见 [通知与验证码](/guide/notifications)。

没有事件时依次检查规则与总开关、对象范围、上游采集、最少样本和连续次数；没有消息时再检查勾选渠道、渠道启用、冷却及发送记录。不要通过对真实对象重复启停来测试通知。
