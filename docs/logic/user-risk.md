# 用户风险识别

中转站用户列表根据注册 IP、短时间注册数量、邮箱模式和近期使用情况累加风险分，用于辅助运营筛查。当前分数不会自动禁用或删除用户。

## 注册 IP 的来源

系统读取 Sub2API 成功的 `auth.register` 审计事件，寻找发生在用户创建时间前 3 秒至后 15 秒内、时间最接近且有客户端 IP 的事件。当前是时间窗口关联，并非强身份追踪。

随后计算同 IP 关联用户数，以及该 IP 任一自然分钟内的注册峰值。读取审计日志失败或超过分页上限时，风险数据可标记不完整；没有匹配日志不能证明用户没有共用 IP。

## 加分规则

| 条件 | 加分 | 说明 |
| --- | --- | --- |
| 同注册 IP 的账号数至少 2 | `25` | 与更多账号条件可叠加。 |
| 同注册 IP 的账号数至少 5 | 额外 `20` | 此时 IP 项合计 45 分。 |
| 同 IP 每分钟注册峰值至少 3 | `25` | 依赖已经匹配到的注册事件。 |
| 命中邮箱模式 | `15` | 当前只检查特定 Gmail 本地部分模式。 |
| 创建不超过 24 小时且所选窗口 Token 为 0 | `5` | 看所选范围用量，不是终身无请求判断。 |

邮箱模式为 `@gmail.com`，本地部分按点或下划线拆成恰好两段，每段至少 2 字符；第二段至少 5 字符且含数字。这是固定启发式，不是邮箱真实性验证。

| 风险等级 | 分数范围 |
| --- | --- |
| 正常 `normal` | 小于 25。 |
| 低 `low` | 25–49。 |
| 中 `medium` | 50–79。 |
| 高 `high` | 至少 80。 |

例如同 IP 关联 5 个账号、分钟峰值 3、命中邮箱模式、又是新账号且无 Token，用当前规则得到 `90` 分，等级为高。

## 如何处理结果

共享出口、企业代理或家庭网络可能自然共用 IP。先检查风险原因、审计来源完整性、用户创建时间和用量，再决定是否手动调整状态或限制。

用户余额、累计扣费、当前并发和风险分是不同指标；风险数据完整性与用量完整性也分别标记。切换时间范围可能改变新账号无 Token 项。

用户批量删除在当前实现中调用远端软删除接口，并先读取角色以跳过管理员。一次最多提交 300 个用户 ID，分别返回成功、失败和跳过结果；风险分本身不会触发这项操作。入口见 [中转站管理](/guide/relay-stations)。
