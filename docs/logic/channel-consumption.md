# 渠道余额与调用记录

渠道的当前余额、余额推算消耗和调用日志金额来自不同过程。余额推算依赖采样密度，不能替代上游账单。

## 自动余额与多账号汇总

自动余额渠道通过渠道连接器读取余额。多个凭据账号分别采集，成功余额求和；失败账号若有上次余额，会暂用旧值，并在渠道保留错误提示。全部账号既采集失败又没有已知余额时，本轮失败。

多账号汇总的余额时间使用已知余额中的最近成功采样时间；某个账号失败不能把旧余额伪装为该账号刚采集成功。部分失败时可能仍更新渠道合计，但不会作为一次全部成功的低余额判断。

自动和手工渠道的低余额条件都要求 `阈值 > 0` 且 `余额 < 阈值`。余额等于阈值不触发；阈值为 0 不开启该告警。后续还要经过 [通知冷却与订阅](/logic/notifications-and-captcha)。

## 余额变化如何记录

```text
变化额 = 新余额 - 前一次余额
变化额 < 0：记录为消耗变化
变化额 > 0：记录为余额增加
```

首次采样只建立基线。变化绝对值不超过 `1e-9` 时不追加变化记录。余额增加的分类名为 `recharge`，但它只说明观测到增加，不会自动证明真实现金充值，也不等于现金账本中的上游充值记录。

## 余额消耗的推算步骤

1. 累加窗口内余额下降记录的绝对值。
2. 排除暂时归零：正余额降至近零，紧接着同渠道在 30 分钟内从近零恢复到至少原余额的 90%，该下降不计消耗。
3. 有窗口起点且能取得可靠起、止余额，并且起点余额高于止点时，用 `起点 - 止点` 限制累计下降的上限。

若起点不高于止点，当前实现不会套用这个净下降上限；没有时间起点的全历史汇总也不做窗口净下降限制。窗口内发生充值时，这种规则可能低估真实累计消耗，它没有完整重建每笔充值与扣款。

例如余额 `100 → 0 → 98`，若恢复满足上述时间条件，归零下降会被排除。余额 `100 → 80 → 130 → 110`，累计下降为 `40`；不能直接用最终余额高于起点来断言零消耗。

## 每日余额基线

每日基线优先取本地当天 00:00 前最后一个正余额；不可用时取当天第一个有效正余额，再考虑当前正余额。零余额不作为有效正基线。

午夜任务和启动补采共同维护每日记录；已有有效记录不被重复覆盖，只有缺失或近零基线才补齐。窗口起点会结合每日记录、起点前快照或窗口内首个正余额选择，因此它可能是近似值。

## 余额趋势的聚合

总余额趋势按各渠道在日内 / 小时内最后一次采样求和。今天、24 小时通常用小时桶，较长窗口用日桶；它不是每桶平均余额，也不是现金收入趋势。

某渠道在该桶没有采样时不会自动沿用前一桶补齐，整桶无记录时也不能据图表空缺断言余额为零。不同渠道采样覆盖率变化可能导致趋势变化，应结合最近成功采样时间核对。

## 手工余额的当前行为

手工渠道不登录上游读取余额、分组或调用日志；同步主要检查已保存余额及低余额条件，不因普通刷新自动扣除中转站调用成本。编辑手工余额后，先检查保存值、相关充值记录和账号绑定。

手工上游充值账本可增减余额，规则见 [成本与倍率](/logic/cost-accounting)。首页对手工渠道的“渠道消耗”可使用关联账号调用成本替代，而渠道页消耗汇总来自余额变化，两页可能不同。

## 调用记录如何采集

自动渠道只有连接器支持使用记录接口时才采集。首次回填向前约 30 天，后续从同步水位向前重叠 10 分钟，按分页读到本轮结束时间；已存在记录按存储的去重规则更新，重叠读取不应重复累计请求。

一个账号失败不妨碍读取其他账号；未完成分页时不应当作全量成功推进水位。未提供使用接口、没有凭据账号、手工余额模式或字段缺失时，空用量不代表上游没有消费。

倍率变化根据连续采样比较，首次发现分组不是一次已知涨跌。采集完整成功后才清理已经消失的分组；部分存储失败时保留旧组，待后续采集处理。
