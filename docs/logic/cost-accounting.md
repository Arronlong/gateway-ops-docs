# 成本与倍率

成本管理同时展示现金账本、渠道余额快照、中转站用户扣费和账号调用成本。它们可互相对账，但不能把不同来源的“消耗”直接相加。

## 现金账本与自动收入

```text
页面总收入 = 区间账本收入 + 区间中转站全站用户扣费
页面总支出 = 区间账本支出
现金净额 = 页面总收入 - 页面总支出
```

收入类别为用户收入、其他收入、采购退款回款；支出类别为账号采购、上游充值、退款、运营支出、其他支出。分类汇总依赖账本记录，不会根据请求日志自动补齐所有现金支出。

自动用户收入读取中转站全站用量，不等于仅当前可见 API Key 账号的扣费合计。已经自动汇入的用户扣费若再次记为手工收入，会重复计入页面总收入。

现金净额不包含全部应收、应付和未登记费用，因此不能直接当作会计利润。页面用户扣费也不证明对应现金已完成收款。

## 实际消耗成本与实时倍率

```text
实际消耗成本 = max(0, 区间账号采购支出 + 区间上游充值支出 - 全部渠道当前余额)
实时倍率 = 实际消耗成本 / 区间中转站用户扣费
```

当前余额是读取时的快照，不是所选窗口期末历史余额；缩短窗口也不会改用期初、期末余额。实时倍率要求用户扣费为正，否则为空；当前按 1:1 处理货币，不执行汇率转换。

按中转站拆分的实际成本使用该站关联的采购与充值金额，没有将全部渠道余额按中转站分摊扣除。也不要假设每个站点都必然有可用的实时倍率字段。

例如窗口内采购 `20`、充值 `100`，当前渠道余额 `30`，用户扣费 `180`，则实际成本为 `90`、实时倍率为 `0.5`。这不等于任一销售组的定价倍率。

## 账号有效成本的解析顺序

| 账号配置 | 使用的成本来源 | 失效时 |
| --- | --- | --- |
| 手工倍率覆盖 `manual` | 显式填写的非负倍率。 | 标记未知，不把负数当有效成本。 |
| 渠道分组覆盖 `channel_group` | 指定监控渠道、指定分组当前非负倍率。 | 关联渠道或分组失效时为未知。 |
| 历史自动关联覆盖 `auto_link` | 兼容读取的历史渠道分组倍率。 | 当前新自动关联已禁用，同步会清理此类历史关系。 |
| 没有显式覆盖 | 账号同步的已知来源倍率，例如成功的上游探测结果。 | 没有来源或没有有效倍率时为未知。 |

显式覆盖优先于账号探测值。存在覆盖但覆盖失效时，当前实现不会静默回退到原探测值。上游账号对象中默认的倍率 `1`，没有明确成本来源时，也不能据此认定成本已知。

成功倍率探测保存成本及观察时间；后续探测失败会保留上一次成功值和原观察时间。旧值仍可参与分析，必须同时看新鲜度。探测与真实调用测试的区别见 [账号操作与测试](/logic/account-operations)。

## 账号调用成本如何计算

远端用量字段 `total_actual_cost` 对应用户扣费，`total_cost` 对应基准调用成本，`total_account_cost` 对应远端报告的账号成本。有效成本倍率已知时：

```text
账号调用成本 = 所选窗口基准调用成本 × 当前有效成本倍率
```

这里用的是“当前倍率”，不是逐条还原每次历史请求时的倍率。更改覆盖倍率后，同一个历史窗口的调用成本可能重新计算并发生变化。

有效倍率未知时，响应会标记成本未知；若远端仍报告有效的正账号成本，汇总可暂用该金额，同时增加未知账号数并将完整性标记为否。既不能说未知账号一定不计金额，也不能把暂用金额当成已核验成本。

查询按账号并发执行，短时缓存约 1 分钟。部分账号失败时保留成功账号的汇总并标记失败数；全部失败时返回错误。账号扣费汇总与全站用户扣费属于不同覆盖范围。

## 渠道关联与差异

当前实现已禁用自动生成渠道与账号的持久关联；同步的协调步骤会清理历史 `auto_link` 覆盖与 `relay_account` 来源的自动分组，并保留用户显式关系。倍率探测成功不会自动创建新的渠道、复制一份自动分组或绑定手工余额渠道。

这与只用于统计归属的 URL 推断不同：统计仍可对没有显式绑定的账号尝试唯一自动余额渠道匹配，但不会因此保存一条新的成本覆盖。


账号汇总到监控渠道时，优先使用显式渠道分组 / 自动关联覆盖；没有这种显式绑定时，才能尝试按 Base URL 找到唯一自动余额渠道。匹配不唯一时不能随意归属；手工余额渠道需明确的关联关系。显式关联失效时不自动换成其他渠道。

URL 匹配会归一主机大小写和默认端口，检查实际端口及路径相等 / 父子路径；主机可按同名、父子域或保守名称规则匹配。因此它不是严格 URL 字符串相等，也不是认证归属校验。仍需唯一候选并人工核对，避免凭站点相似名称判断归属。

```text
渠道成本差异 = 区间该渠道上游充值 - 区间映射到该渠道的账号调用成本
```

充值与调用成本发生时间不同，且账号绑定、倍率和远端读取可能不完整。差异用于排查，不是自动认定损益。余额消耗另见 [渠道余额与调用记录](/logic/channel-consumption)。

## 账本修改的副作用

手工来源的支出记录，类别为上游充值且关联手工余额渠道时，创建会增加余额；编辑先冲回旧关联金额再应用新金额；删除会冲回原充值。余额最低归零，并写余额快照。自动余额渠道的账本不直接修改远端余额。

历史导入来源的记录即使能编辑，也不按手工充值规则再次调整余额。本地账号采购来源由号池维护，见 [本地号池与采购账本](/logic/local-account-lifecycle)。

对账时按“时间窗口 → 账本来源 → 账号成本来源 → 渠道绑定 → 完整性与观察时间”的顺序核对。
