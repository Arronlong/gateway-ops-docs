# 延迟与稳定性

首字时间、总耗时和输出速度描述不同维度。时间桶仍用于观察延迟分布；账号卡片上的四项综合评分另行结合缓存、实际尝试成功率和相对延迟波动，公式见 [缓存指标与健康评分](/logic/cache-and-health-score)。后台 [自动优先级](/logic/auto-priority) 仍使用独立的延迟排序分。

## 基础指标

| 指标 | 计算方法与单位 | 缺失时 |
| --- | --- | --- |
| 首字时间 | 请求发起到首个响应内容，单位 ms。 | 不参与该项延迟评分。 |
| 总耗时 | 请求开始到完成，单位 ms。 | 无有效值时不计算输出速度。 |
| 输出速度 | `输出 Token 数 × 1000 / 总耗时毫秒`，单位 tokens/s。 | Token 数及耗时都必须为正，否则为空。 |
| P50 / P95 | 有效样本排序后，按 `(样本数 - 1) × 分位比例` 的位置线性插值。 | 没有有效样本时为空。 |

输出速度的分母是总耗时，不会减去首字等待时间。桶输出速度 P50 / P95 先计算每条请求的速度，再求百分位；不能用桶总 Token 数除以桶总耗时替代。

## 成功率与时间桶

中转站样本状态码为 `0` 或 `200–399` 时计为成功。渠道样本使用结果字段；结果未知的样本不进入已知结果成功率的分母。

时间桶使用左闭右开区间 `[开始, 结束)`。中转站桶请求数统计落入窗口的样本，成功率为成功数除以请求数。空桶即使后端有零值，也应结合请求数判断“无数据”，不能解释为真实的 0% 成功率。

页面提供自动粒度及 `5 / 10 / 30 / 60 / 180 / 360 / 720` 分钟。7 天与 30 天窗口使用自动粒度或至少 60 分钟，过细选项会归一为 60 分钟。

有请求但上游未提供任何延迟字段时，悬停提示会明确区分“已有调用、缺少延迟”和“无调用”，时间桶色块按桶成功率着色；成功率也未知时保留中性色。已有延迟时，色块综合成功率与延迟阈值，采用较差的状态显示；空桶仍按无调用展示。成功率或延迟缺失不等于真实 0。

## 延迟如何映射到 0–100 分

| 项目 | 警告阈值 W | 严重阈值 B |
| --- | --- | --- |
| 首字时间 | 10000 ms（10 秒） | 30000 ms（30 秒） |
| 总耗时 | 60000 ms（60 秒） | 180000 ms（180 秒） |

```text
耗时 x <= W：100 分
耗时 x >= B：0 分
中间范围：100 × (B - x) / (B - W)
```

这是固定阈值映射，分数不等于请求的真实可用性概率。缺少某项时只平均已有项，不会把缺失首字时间当作 0 ms。

## 时间稳定性与账号综合评分

本页的延迟泳道以时间桶呈现 P50 / P95，供定位尾延迟和时间分布；账号卡片上的“综合评分”不再使用旧版的三项加权规则。当前评分由成功率、稳定性、缓存命中和延迟四项各占 25%，并受系统设置的近期统计窗口控制。

评分任一因素未知时显示 `--`，不把缺项当零分，也不重新分配权重。有效尝试少于 10 次时会提示低置信度。具体口径及稳定性公式见 [缓存指标与健康评分](/logic/cache-and-health-score)。自动优先级仍使用独立的延迟排序逻辑，不能用综合评分推断其执行顺序。

## 查看百分位与调用明细

悬停非空时间桶，可查看请求数、成功率、首字时间 P50 / P95、总耗时 P50 / P95 和输出速度 P50 / P95。P50 描述中位表现，耗时 P95 描述较慢一侧的尾延迟；速度 P95 则描述较快一侧，不能将两者都理解为最差表现。

点击非空桶可打开调用明细，后台默认最多读取该桶最近 30 条；桶统计覆盖该桶有效样本，百分位并非只由当前明细列表重新计算。点击近期调用时优先打开它所在桶的明细，没有对应桶时显示该条记录。

后台明细显示可用的请求时间、模型、结果、耗时、输出速度和 Token 信息。字段缺失时保留缺失提示，不把未知成功状态计为失败。

## 关联调用与时间桶对照

渠道与中转站通过当前账号关联进行双向对照。近期调用优先在 10 分钟内匹配模型或 Token 总数，未找到时按样本相对位置回退；时间桶按开始时间、区间覆盖和最近开始时间对齐。

完整规则、账号范围和排查步骤见 [渠道与中转站调用对比](/logic/call-comparison)。位置回退和时间桶对齐均需核对实际时间范围，不能仅凭并排展示断言是同一请求。
