# 公开页面的数据规则

公开分组监控、模型价格和官方服务状态有独立来源，只返回允许公开的只读视图。分组监控从 v1.1.2 起只读取后台持久快照，不因访问量或页面切换直接请求上游管理接口。

## 分组监控范围与持久快照

仅支持 `today`、`24h`、`7d`、`30d`，默认滚动 24 小时；不支持 `custom`、`all` 或任意起止时间，非法范围返回 400。页面历史范围与近期缓存 / TPS 统计窗口分别计算。

后台为开启公开监控的分组读取用量与错误记录，按 UTC 日保存压缩明细，再生成四个固定区间的安全聚合快照。优先从最近日期准备，可用的短区间先发布，不必等待所有 30 天均完成。历史日数据在完整且来源未变时复用：前一天约每 5 分钟重查，更早完整日期约每 24 小时重查，当天继续补取；只保留计算所需窗口及边界日，不是无限历史仓库。

计算默认每 30 秒，在“系统设置 → 后台任务与同步 → 分组监控计算频率”保存后可设为 10–3600 秒。它与浏览器每 30 秒读取快照是两套周期；关闭页面不停止计算，页面刷新不强制重算。启动时后台预热，上一轮未结束跳过下一轮，单轮最长约 15 分钟；过短周期不保证每轮都立即完成。

| 快照状态 | 解读方式 |
| --- | --- |
| `preparing` | 首次历史尚未补齐、新增监控组或连接源变更后等待有效数据；不回退页面直查上游。 |
| `ready` | 已有可读取的快照；仍需查看更新时间，不代表实时探活。 |
| `stale` | 后台最近失败，或快照距今超过配置计算间隔的 3 倍；保留最近成功结果并提示旧数据。 |

PostgreSQL 保存快照，重启后可读取来源匹配的已有结果。当前组名、状态及公开开关仍重新核对：关闭的组从公开结果移除，新增组未准备好时提示准备中；站点类型、地址或管理员凭据改变后不复用旧来源快照。无有效数据时不补造 0%、100% 或正常状态。

## 分组状态与最终成功率

后台合并远端成功用量和请求错误，通过请求 ID / 客户端请求 ID 关联，排除已最终成功请求的中途故障转移错误；同一最终失败请求保留最后失败，无关联 ID 的错误保留为独立事件。失败数不等于所有重试日志行数。

| 状态 | 当前条件 |
| --- | --- |
| 已停用 `disabled` | 分组不是 `active`。 |
| 未知 `unknown` | 活跃分组缺少完整有效数据。 |
| 空闲 `idle` | 数据完整，但窗口没有调用。 |
| 不可用 `unavailable` | 最新连续至少 3 次失败。 |
| 波动 `degraded` | 最新连续 1–2 次失败。 |
| 可用 `available` | 最近一次调用成功。 |

从最新记录向前判断连续失败，遇成功停止。首行成功率为窗口成功数除以成功与最终失败总数，空窗口不显示虚构成功率。明细最多 60 条，区间统计不是只统计这 60 条；后台仍需完整分页，超过安全上限则失败并保留旧快照，不将残缺采集发布成完整结果。

## 延迟、输出 Token 与速度分位

窗口分成 60 个左闭右开时间桶，P50 / P95 只使用有效相应字段。v1.1.2 补充调用输出 Token 和桶内输出速度 P50 / P95，单条速度为输出 Token ÷ 总耗时秒数，再求百分位；缺少有效输出或耗时不伪装为零速度，也不以聚合 TPS 替代速度分位。

色块有延迟时直接使用与浮层相同的首字 / 总耗时阈值，不再被失败结果额外压低颜色；没有延迟时才按已知请求结果回退，结果也未知则中性色。这与分组可用 / 波动 / 不可用状态是不同维度。公式见 [延迟与稳定性](/logic/latency-and-stability)。

## 近期缓存与 TPS 环形指标

v1.1.2 移除含重试成功率环形展示，保留缓存和 TPS 两项；历史最终成功率、请求结果和错误采集保留。两项由后台按组计算，不从公开返回的最多 60 条明细反推。

使用全局 `recent_metrics_window_hours` 和 `recent_metrics_limit`，默认 1 小时、60 条，范围 1–24 小时、1–200 条。以本轮后台计算时间前 45 秒为截止点，再向前回看统计时长，按时间倒序最多取所设数量；辅助 / 图片等过滤后不另补更早请求。因此接近午夜选择“今天”时，近期指标仍可含前一天记录，选择 7 天 / 30 天也不自动扩大近期窗口。

| 指标 | 计算与边界 |
| --- | --- |
| 缓存命中率 | 缓存读取 Token 总量 ÷（输入 + 缓存读取 + 缓存创建 Token 总量），按 Token 加权；无有效 Token 总量时不可用。 |
| TPS | 有效输出 Token 总数 ÷ 有效请求总耗时秒数。排除辅助、探测、cyber、进行中及图片调用；负输出或非正耗时排除，零输出仍保留有效耗时。 |
| TPS 进度 | `min(100, TPS × 2)`，50 TPS 及以上封顶 100，中心为 Token/s；不加入三项健康评分或自动优先级。 |

原始用量和错误各自去重，时间无效的记录跳过。有效上游失败仍可在 TPS 中贡献零输出耗时，不把最终请求成功率当作速度计算条件。用量和错误两类读取均需完整，失败时不发布新的残缺快照；已选窗口无有效样本则相应指标不可用。缓存创建汇总为 0 时使用 5 分钟与 1 小时字段之和，负 Token 按零处理。

错误采样只纳入当前组或未带组 ID 的 provider / upstream 错误，排除客户端归属、其他分组和 HTTP 499；仅处理有效 HTTP 400–599。`request_type` 支持字符串、数字、空值和缺省，类型兼容不代表数字自动等同于某种图片或探测分类。

公开 `recent_metrics` 是汇总投影，不公开原始采样数组、请求 ID、用户 / 账号 ID 或凭据；失败摘要只保留模型及安全原因分类。浏览器本地缓存用于恢复画面，仍应以 `updated_at`、`sync_status` 和错误提示判断新鲜度，不能把“读取成功”当作“刚刚重新采集”。

## 模型目录与价格

模型目录依赖销售组对应的有效网关 API Key，不使用管理员 API Key 直接充当网关 Key。目录与报价按当前活跃分组、渠道和模型适配关系生成。

当前价格来源包括系统默认价格、渠道覆盖、渠道覆盖加默认补全、分组独立生图定价、不可用。渠道覆盖可以只指定部分价格字段，未覆盖项回退系统默认；分组没有关联渠道时可使用系统默认价格。开启生图、启用独立图片价格且至少有一个分辨率价格的组，可对识别到的生图模型使用分组独立报价；它与普通渠道覆盖的来源不同。

页面保留输入、输出、缓存、图片等价格维度，以及上游提供的区间 / 时间 / Fast / Flex 等规则。每 Token 价格转为每百万 Token 展示时乘 `1000000`；按次计费不乘这个因子。图片分辨率价格与文本 Token 价格不能混用，分组倍率也要单独核对。

模型存在不代表所有价格字段都存在。没有来源的字段为空 / 不可用，不能补成免费。

价格服务端缓存约 10 分钟；重新生成失败且已有旧视图时可能返回旧视图，更新时间保持原值。同步会使相应缓存失效，但上游不可达时仍应检查错误和新鲜度。

## 官方服务状态

系统聚合 OpenAI、Claude 与 DeepSeek 官方状态页，读取当前组件、事件及计划维护，短时缓存约 30 秒。主摘要读取失败时显示未知及获取失败提示，不把“请求失败”转成“服务正常”。

历史展示最近 60 天，使用 UTC 自然日。事件从开始时间覆盖到解决时间或当前时间，再映射到组件 / 产品分组；无法识别影响组件的事件可能按宽范围归属。

```text
OpenAI / Claude 展示可用率 = 状态为 operational 的天数 / 已生成历史天数 × 100%
```

这个指标按天分类计算，不是按故障分钟计算；某天短暂故障也可能使该天不计为正常。它描述官方状态历史，不是 GatewayOps 自身监测的请求成功率，也不代表中转站出口是否可达。

DeepSeek 使用官方状态页的当前摘要、结构历史和事件列表适配组件及分组，沿用 30 秒缓存和 12 秒请求超时。分组 / 组件的 `uptime` 直接使用官方返回值；`uptime_available` 区分缺失，不用按天公式替代。组件可用起始时间之前的日期标记未知。主摘要获取失败或没有有效组件时显示未知；历史结构失败会清空相应历史，历史或事件列表缺失时提示不完整，不因当前可读而补造历史正常。

页面入口与使用前提见 [公开页面](/guide/public-pages)。
