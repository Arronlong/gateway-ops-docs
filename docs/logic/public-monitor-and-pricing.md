# 公开页面的数据规则

公开分组监控、模型价格和官方服务状态有各自数据来源。它们可免后台登录访问，展示的是可公开的只读视图；不要根据其中一个页面推断全部后台数据都可公开。

## 分组监控与状态

只有开启公开监控的分组进入相应视图。默认窗口为滚动 24 小时，也支持今天、7 天和 30 天；服务端短时缓存约 15 秒。

系统合并远端成功用量记录与请求错误。通过请求 ID / 客户端请求 ID 关联后，已最终成功请求的中途故障转移错误被排除；同一最终失败请求保留最后失败，没有关联 ID 的错误保留独立记录。因此失败数不等于所有重试错误日志行数。

| 状态 | 当前条件 |
| --- | --- |
| 已停用 `disabled` | 分组不是 `active`。 |
| 未知 `unknown` | 活跃分组的数据读取不完整。 |
| 空闲 `idle` | 数据完整，但窗口内没有调用。 |
| 不可用 `unavailable` | 最新连续至少 3 次失败。 |
| 波动 `degraded` | 最新连续 1–2 次失败。 |
| 可用 `available` | 最近一次记录成功。 |

按最新记录向前检查连续失败，遇到成功停止。成功率为窗口成功数除以成功与最终失败总数；空窗口不显示虚构的 100% 或 0%。卡片近期明细最多 60 条，窗口统计使用窗口事件，并非只统计这 60 条。调用和错误记录均按页读取；如果上游页数估算偏小但末页仍满页，系统会继续读取，直到不足一页，避免历史窗口提前截断。超过安全分页上限会返回错误，不会把不完整结果伪装成完整历史。

延迟桶将窗口分成 60 段，按 `[开始, 结束)` 归属；P50 / P95 只使用有相应耗时的记录。有调用但没有延迟时色块按已知成功率显示，成功率也未知时使用中性色，并在悬停时说明上游缺少延迟字段。公开失败摘要只保留模型及安全原因分类，不输出原始凭据、内部端点、账号名或请求 ID。

没有真实调用时可以是空闲，即使配置正确也不会自动变成可用。这套状态没有额外主动探活，不能作为实时 SLA 保证。

## 分组近期环形指标

v1.0.8 新增 `recent_metrics`，由后端按公开分组聚合，前端复用三项环形展示。它与上节按最终请求结果合并后的状态、历史成功率和调用列表使用不同样本，不从公开返回的最多 60 条明细反推指标。

### 窗口与采样

使用系统设置的 `recent_metrics_window_hours` 和 `recent_metrics_limit`，默认 1 小时、60 条，允许 1–24 小时、1–200 条。以本次取数时刻前 45 秒为截止点，向前回看所设小时数，保留窗口边界内记录；按时间倒序最多取所设数量，不足时使用已有记录，不补造样本。

后台会读取足以覆盖“页面历史范围”和“近期指标窗口”两者的用量 / 错误记录，再分别计算。因此选择“今天”且接近午夜时，近期指标仍可能包含前一天的调用；选择 7 天或 30 天也不会把近期指标自动扩大为同样长度。近期指标数量不改变原有调用明细的 60 条限制。

用量和错误各自按正记录 ID 去重，时间无效的记录跳过；缺少正 ID 的记录不凭空推断为重复。近期指标保留原始尝试，不使用按请求 ID 合并最终结果的历史流程。筛选辅助或图片等样本后，不额外从更早记录补齐数量。

### 公式与有效性

| 指标 | 计算与边界 |
| --- | --- |
| 缓存命中率 | 缓存读取 Token 总量 ÷（输入 + 缓存读取 + 缓存创建 Token 总量）。缓存创建汇总为 0 时采用 5 分钟与 1 小时创建量之和；负数按 0 处理，没有有效 Token 总量为不可用。聚合不以请求最终成功为前提，也不使用成功率 / TPS 的辅助调用排除条件裁剪 Token。 |
| 含重试成功率 | 成功的有效尝试数 ÷ 有效尝试数。用量状态码为 0 或 200–299 时计成功；进行中尝试保留在分母但不算成功。辅助、探测及已确认的 cyber 调用从成功 / 失败和分母中排除。 |
| TPS | 有效样本输出 Token 总数 ÷ 请求总耗时（秒）。排除辅助、探测、cyber、进行中、请求类型或模型名识别出的图片调用；负输出或非正耗时不参与，零输出仍保留有效耗时。无有效耗时为不可用，有耗时但输出全为零为 0 TPS。 |
| TPS 环形进度 | `min(100, TPS × 2)`，50 TPS 及以上封顶 100；中心显示 Token/s。此处是分组指标展示，不改变后台四项健康评分或自动优先级。 |

错误样本仅纳入当前分组或上游未带组 ID 的记录，要求归属为 provider，或非 client 且阶段为 upstream；仅保留 HTTP 400–599，排除 499。客户端错误和明确属于其他分组的错误不进入指标。`request_type` 支持字符串、数字、空值和缺省；兼容字段类型不代表数字类型自动等同于某种探测或图片分类。

失败后重试成功时，历史最终成功率可为 100%，近期环形指标仍可能包含先前失败尝试。例如两次上游失败后一次成功，在三次均进入样本且不被排除时，含重试成功率为 1/3。错误若提供有效耗时但没有输出，TPS 仍保留这部分零输出耗时；因此 TPS 也不能由最终成功请求的速度替代。通用公式见 [缓存指标与健康评分](/logic/cache-and-health-score)。

### 完整性、缓存与公开字段

用量和错误两类读取都成功，才计算该分组近期指标。任一类失败或分页未完整读取时，三项数值保留不可用，不用残缺数据宣称 100% 成功或 0 TPS。完整但空窗口同样不可用；缺少 Token 总量或有效耗时则只影响相应指标。前端遇到未返回 `recent_metrics` 的旧响应也显示不可用。

服务端约 15 秒缓存按站点、页面历史范围、统计时长和最近数量区分，避免修改采样设置后命中旧参数结果。浏览器监控缓存版本为 3，旧版本缓存不复用；页面约每 30 秒刷新一次，修改设置不会实时推送到已打开页面。请求失败时已有画面可能继续保留，应结合错误提示和更新时间判断。

公开接口仅增加汇总的 `recent_metrics`：窗口、数量上限、选中数量、最新时间、比例、Token 总量、成功尝试数、TPS 耗时与模型等。该对象不返回原始采样数组、请求 ID、用户 ID、账号 ID 或凭据；原有公开调用记录仍沿用安全字段范围，不因新增指标扩大公开权限。

## 模型目录与价格

模型目录依赖销售组对应的有效网关 API Key，不使用管理员 API Key 直接充当网关 Key。目录与报价按当前活跃分组、渠道和模型适配关系生成。

当前价格来源包括系统默认价格、渠道覆盖、渠道覆盖加默认补全、分组独立生图定价、不可用。渠道覆盖可以只指定部分价格字段，未覆盖项回退系统默认；分组没有关联渠道时可使用系统默认价格。开启生图、启用独立图片价格且至少有一个分辨率价格的组，可对识别到的生图模型使用分组独立报价；它与普通渠道覆盖的来源不同。

页面保留输入、输出、缓存、图片等价格维度，以及上游提供的区间 / 时间 / Fast / Flex 等规则。每 Token 价格转为每百万 Token 展示时乘 `1000000`；按次计费不乘这个因子。图片分辨率价格与文本 Token 价格不能混用，分组倍率也要单独核对。

模型存在不代表所有价格字段都存在。没有来源的字段为空 / 不可用，不能补成免费。

价格服务端缓存约 10 分钟；重新生成失败且已有旧视图时可能返回旧视图，更新时间保持原值。同步会使相应缓存失效，但上游不可达时仍应检查错误和新鲜度。

## 官方服务状态

系统聚合 OpenAI、Claude 与 DeepSeek 官方状态页，读取当前组件、事件及计划维护，短时缓存约 30 秒。主摘要读取失败时显示未知及获取失败提示，不把“请求失败”转成“服务正常”。

历史展示最近 60 天，使用 UTC 自然日。事件从开始时间覆盖到解决时间或当前时间，再映射到组件 / 产品分组；无法识别影响组件的事件可能按宽范围归属。

```text
OpenAI / Claude 展示可用率 = 状态为 operational 的天数 / 已生成历史天数 × 100%
```

这个指标按天分类计算，不是按故障分钟计算；某天短暂故障也可能使该天不计为正常。它描述官方状态历史，不是 GatewayOps 自身监测的请求成功率，也不代表中转站出口是否可达。

DeepSeek 使用官方状态页的当前摘要、结构历史和事件列表适配组件及分组，沿用 30 秒缓存和 12 秒请求超时。分组 / 组件的 `uptime` 直接使用官方返回值；`uptime_available` 区分缺失，不用按天公式替代。组件可用起始时间之前的日期标记未知。主摘要获取失败或没有有效组件时显示未知；历史结构失败会清空相应历史，历史或事件列表缺失时提示不完整，不因当前可读而补造历史正常。

页面入口与使用前提见 [公开页面](/guide/public-pages)。
