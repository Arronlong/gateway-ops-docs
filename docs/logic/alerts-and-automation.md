# 预警判定与安全自动化

本页对应 v1.0.5 的规则引擎。操作入口见 [预警中心](/guide/alerts)；这套引擎与原有自动调组、自动优先级及传统通知是不同处理链路，不应把一处开关当成所有自动操作的总开关。

## 对象与指标

| 对象与指标 | 判定口径 |
| --- | --- |
| 渠道倍率变化 `channel_rate_change` | 在窗口内读取已有模型倍率变化，按方向与百分比 / 绝对差值取最大有效变化；模型属性过滤参与匹配，不是任取一条分组倍率。 |
| 渠道余额低 `balance_low` | 取渠道账号的最低有效余额，余额小于或等于阈值触发。 |
| 中转站账号倍率变化 `rate_change` | 与最近正常倍率基线比较，可选上涨、下跌或双向；异常及恢复过程中冻结基线。百分比模式下缺失或零基线不能判定。 |
| 中转站账号消耗 `account_spend` | 窗口累计账号成本达到阈值。优先用上游账号成本，否则用请求原价乘账号成本倍率，缺失时不拿用户扣费替代。 |
| 中转站账号稳定性 `account_stability` | 选择错误率、首字耗时 P95、请求耗时 P95 或末尾连续失败请求数。错误按状态码至少 400 判断；耗时单位为毫秒。 |
| 中转站用户消耗 `user_spend` | 窗口累计用户实际扣费达到阈值，不是账号采购成本或现金账本收入。 |
| 中转站用户多 IP `user_multi_ip` | 窗口去重后的非可信来源 IP 数达到阈值；支持 IPv4、IPv6、单 IP 与 CIDR 白名单，缺失或无效地址为未知。 |
| 中转站用户余额低 `user_balance_low` | 用户余额小于或等于阈值触发；与渠道账号余额不同。 |

兼容旧账号余额规则时，账号对象的 `balance_low` 读取关联渠道账号余额，不是远端用户余额；新建时应优先选清楚的渠道或用户余额对象。渠道规则不支持远端自动化，中转站管理支持 New API 不代表预警自动化支持 New API。

### 公式与历史基线

```text
倍率变化百分比 = (当前倍率 - 基线倍率) / abs(基线倍率) × 100
错误率 = 窗口内状态码至少 400 的记录数 / 窗口请求数 × 100%
账号成本 = sum(上游账号成本；缺失时使用请求原价 × 账号成本倍率)
用户消耗 = sum(用户实际扣费)
```

倍率下跌取反，双向取绝对值；渠道倍率使用变化记录自己的旧值，账号倍率使用规则保存的正常基线。P95 对有效正耗时排序，取 `ceil(样本数 × 0.95)` 对应值。预警错误率使用该规则的用量窗口，不是 [重试感知成功率](/logic/cache-and-health-score) 的去重口径。

消耗规则可叠加历史基线倍数：最近 7 天相同时间窗口的均值，至少 3 个完整历史窗口；必须同时达到金额阈值和基线倍数。基线缺失或非正时返回未知。升级后历史覆盖不足可能需要等待采集，不能把未知当成未超标。

## 条件参数与默认值

| 参数 | 新建默认值 | 有效范围或含义 |
| --- | --- | --- |
| 统计窗口 `window_seconds` | 900 秒 | 60–86400 秒；用量规则按有效同步水位向前取窗口。 |
| 阈值 `threshold` | 表单初始值 20 | 不是所有指标通用的建议值。余额允许 0，其他指标须为正；错误率不超过 100%，IP 数须为至少 2 的整数。 |
| 最少请求 `min_requests` | 0 | 0–1000000，样本不足为未知。 |
| 连续触发 / 恢复次数 | 各 3 次 | 各 1–100 次；按有效新采样累计，不按页面刷新次数。 |
| 命中窗口 `hit_window` | 留空 | 最近 M 次中命中 N 次，M 至少为 N 且不超过 100。 |
| 恢复阈值 | 留空 | 配置时必须留滞回区间：余额高于触发值，其他指标低于触发值。 |
| 历史基线倍数 | 留空 | 仅消耗规则可用，须大于 1。 |
| 属性筛选组合 | 全部匹配 | 可选任意匹配，最多 20 条；每个筛选值不超过 256 字。 |
| 规则级别 | 警告 | 提示、警告、严重；级别本身不改变公式。 |
| 自动化 / 自动恢复 | 不执行 / 关闭 | 每条规则最多一个启用动作，目标类型必须匹配。 |
| 通知冷却 | 30 分钟 | 60 秒至 7 天，区别于传统低余额通知的全局冷却。 |

## 数据完整性与事件状态

倍率样本要求约 3 分钟内有效，渠道或关联账号余额要求约 10 分钟内有效；用量水位需新鲜且已经回填覆盖整个窗口。任一需要的余额不可用、用量不完整、状态码或耗时不足时，不猜测结果。最少请求限制也在判定前检查。

正常 `normal` → 待触发 `pending` → 异常 `firing` → 恢复中 `recovering` → 已恢复 `recovered`。未知 `unknown` 会清空累计证据；已有活动异常遇到未知时保持异常，不会因此自动恢复。相同或倒退采样时间不增加次数。滞回区间不会触发新异常，也不累计恢复次数。

无活动事件时修改判定会重新累计证据；有活动事件时禁止修改范围、条件及动作，只能改名称、通知、冷却、备注和启用状态。属性筛选不应让已产生异常的对象因停用后不再匹配而被直接遗忘，活动事件仍参与后续恢复核对。

## 自动化与安全恢复

支持停止 / 恢复账号调度、停用 / 启用用户，每条规则仅一种动作。远端读写目前只适配 Sub2API；New API 及不支持的能力拒绝执行，不回退到登录、Token 续期、测智或其他管理操作。指定目标必须为一个站点中的远端数字 ID。

执行前持久化动作占位，再核对远端状态并写入；并发、重启或超时后不自动重放结果不确定的写请求。原本就处于停用状态的对象不会被本事件取得恢复所有权。是否触发事件、通知是否成功、远端动作是否成功分别记录，不能互相替代。

停用动作可选条件恢复后的反向启用，恢复前同时检查：本事件成功停用、持久化所有权、远端当前状态与版本指纹、人工介入标记、其他规则是否仍持有停用约束。无法确认时跳过或保留待处理记录；人工进行了相同状态操作也会影响恢复所有权。直接启用动作仍受其他规则停用约束，且不支持恢复后反向停用。

确认仅代表已查看；关闭仅结束事件，不恢复远端。暂停规则会停止其评估及自动恢复；存在未恢复事件不能删除规则。人工处理前应同时查看其他规则，不用强制启用代替根因排查。

## 采集频率、设置与保留

预警设置存入数据库，通过受后台认证约束的 `GET/PUT /api/alerts/settings` 管理；v1.0.5 没有独立的前端总开关和频率表单，也不是一组新增环境变量。接口字段如下：

| 字段 | 默认值 | 范围 |
| --- | --- | --- |
| `enabled` | `true` | 预警评估及采集总开关。 |
| `evaluation_interval_seconds` | 60 | 固定 60 秒。 |
| `rate_interval_seconds` | 60 | 60–120 秒。 |
| `usage_interval_seconds` | 60 | 60–120 秒；用于消耗、稳定性及 IP 数据。 |
| `balance_interval_seconds` | 300 | 300–600 秒。 |

只为需要相应数据的启用规则安排预警采集，正在运行的任务跳过重复调度。用量任务只补所需增量范围，不执行完整账号快照、主动测速或付费测智；渠道 / 中转站已有同步任务仍按自身配置运行。默认余额规则需 3 份新余额样本，通常约 10–15 分钟再加评估延迟，不能拿一分钟评估周期推断一分钟就会触发。

预警指标样本保留 8 天；事件与动作保留用于审计，通知日志沿用原有保留策略。预警事件及动作不等于 [定时任务执行历史](/logic/task-execution-history)，查询入口和含义不同。

## 消息、冷却与失败

通过规则单独关联已有通知渠道，只发送给已勾选且启用的渠道；空关联表示不发送。消息内置规则、级别、站点对象、指标与阈值、窗口、时间、自动化结果和事件信息。

异常通知冷却按事件与通知渠道独立持久化；恢复通知另行发送一次。失败渠道在后续评估重试，成功渠道不因其他渠道失败重复投递。恢复通知失败不阻断事件关闭或下一次异常自动化。单次投递内部仍复用原通知发送器的有限重试，通知重试不重做远端动作。

传统通知的空订阅视为全部、全局低余额冷却及倍率合并仍见 [通知与验证码规则](/logic/notifications-and-captcha)，不要把这些语义套用到预警规则。
