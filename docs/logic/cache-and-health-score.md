# 缓存指标与账号健康评分

渠道列表和 Sub2API 中转站账号列表展示近期缓存命中率、重试感知成功率与 TPS 输出速度；列表也可按这些指标排序，并显示四项综合评分。统计时长和最近数量在系统设置的“监控指标”区配置。

v1.0.8 的公开分组监控也展示三项近期环形指标，复用相同统计时长与最近数量；它由后端合并用量和错误记录计算，且要求两类读取均完整，不应把后台前端样本逻辑直接套到所有公开字段。分组采样、失败归属、缓存和最终结果差异见 [公开页面的数据规则](/logic/public-monitor-and-pricing)。

## 统计窗口

窗口长度可设置为 1–24 小时，默认 1 小时；最近数量可设置为 1–200 的整数，默认 60。两者同时限制统计样本，不是二选一。

1. 以当前时刻前 45 秒为截止点，向前回看所设小时数，排除无效时间与窗口外记录。
2. 将已读取的窗口内样本按时间倒序排列，最多取所设最近数量。
3. 仅用这些样本计算缓存命中率、重试感知成功率、稳定性及延迟，再计算综合评分；TPS 也从同一批样本筛选有效文字计量；不足所设数量时使用已有记录，不补成零值。

例如设置 4 小时、100 条时，指标使用截止点之前 4 小时内最近的最多 100 条。扩大时间窗不等于读取全部历史，仍受数量上限、已同步和已返回样本限制。最近调用条带使用数量上限展示原始近期记录，不保证与指标经过时间窗筛选后的分母相同。

修改统计时长或最近数量后，点击同一卡片标题行的“保存监控设置”。两项设置保存在 PostgreSQL，并同时应用于渠道和中转站账号的缓存命中率、重试感知成功率、TPS、综合评分及相关排序；同时影响最近样本读取数量与前端近期统计，不改变后端历史保留、采集周期、预警窗口或自动优先级规则；历史时间桶也不按此数量裁剪。指标公式与四项等权保持原有规则。

## 缓存命中率

```text
缓存命中率 = 缓存读取 Token 数
           / (输入 Token 数 + 缓存读取 Token 数 + 缓存创建 Token 数)
           × 100%
```

缓存创建 Token 数优先使用汇总字段；字段未提供时，将 5 分钟和 1 小时缓存创建量相加。按整个统计窗口的 Token 数汇总后计算比例，不是先算每次请求的比例再简单平均，也不是“命中请求数 / 请求总数”。

没有缓存命中的普通输入仍计入分母。没有有效 Token 总量时显示未知；不能把未知当作 0% 或 100%。

## 重试感知成功率

```text
重试感知成功率 = 统计窗口内成功的有效尝试数 / 有结果的有效尝试数 × 100%
```

每次上游尝试分别计数。请求先失败、重试后成功时，失败和成功各计一次，因此不会只用最终请求结果掩盖重试失败。已知结果优先使用调用结果；缺少结果时，HTTP 200–299 作为成功，其他有效 HTTP 状态作为失败。

辅助调用、探测调用及已确认的 cyber 请求不计入分子或分母。进行中的文本尝试仍计入分母；仍在等待完成的图片尝试计入结果时按其已知状态处理。无法确定结果的样本不强行标记成功或失败。

## TPS 输出速度与独立评分

TPS（每秒输出 Token 数）显示在渠道与中转站账号的近期环形指标中。先按本页统计窗口和最近数量选样本，再在已选集合中筛选有效计量；排除记录后不会另补更早的调用。

```text
TPS = 有效样本输出 Token 总数 / 有效样本请求总耗时（秒）
TPS 评分 = min(100, TPS × 2)
```

例如两个有效请求分别输出 40 / 90 Token、耗时 2 / 3 秒，TPS 为 `(40 + 90) / (2 + 3) = 26`，评分为 52。分母包含请求总耗时，不减去首字等待时间；既不是各次 TPS 的简单平均，也不是观察窗口的墙钟吞吐量。

| 样本情形 | 处理规则 |
| --- | --- |
| 辅助、探测或已确认的 cyber 调用 | 使用现有分类与标记排除。 |
| 进行中请求 | `in_progress` 或 `attempt_status` 为进行中时排除，避免未完成耗时进入分母。 |
| 图片请求 | 请求类型含 `image`，或模型名命中已有图片模型识别规则时排除，包括渠道仅返回模型名的图片补计量。 |
| 输出 Token | 必须为有限非负数；零值或省略的零值按 0 计入，仍保留该请求有效耗时，不借此抬高速度。 |
| 总耗时 | 必须为有限正数；缺失、0、负数或无效数不参与。 |
| 请求结果 | 不额外要求 HTTP 成功；已经结束且满足以上条件的尝试仍按实际输出与耗时计算，不等同于成功率。 |

环形中心显示原始 TPS（Token/s），环形进度与列表的“TPS 评分”使用上述封顶分值：0 TPS 为 0 分，25 TPS 为 50 分，50 TPS 及以上均为 100 分。因此选择该排序时，高于 50 TPS 的项目不会继续按原始速度拉开评分。没有有效计量时显示 `—` / 不可用；有有效耗时但输出全为零时是 0 TPS，不是未知。

悬停可查看参与模型、统计时长、数量上限、输出总量、总耗时及评分过程。多个模型可能合并在同一环形指标中，应结合模型清单判断，不能把它当成同模型的标准性能测试。TPS 有效计量数也可能少于窗口内选中样本数。

TPS 仅作为独立指标与排序依据，不是综合健康评分的第五项，不改变四项各 25% 的权重，也不改变后台自动优先级。时间桶的输出速度 P50 / P95 先计算每条速度再求百分位，不能用本页聚合 TPS 代替，见 [延迟与稳定性](/logic/latency-and-stability)。

## 四项综合评分

综合评分由四项等权组成，各占 25%，分值为 0–100：

| 因素 | 计算说明 |
| --- | --- |
| 成功率 | 使用上述重试感知成功率，换算为百分制。 |
| 稳定性 | 对成功尝试的首字时间和总耗时分别计算波动分，再乘连续失败系数。 |
| 缓存命中 | 使用上述按 Token 加权的缓存命中率。 |
| 延迟 | 只看成功尝试；每次对有效的首字时间分和总耗时分取平均，再对请求平均。 |

首字时间在 10 秒内、总耗时在 60 秒内为 100 分；首字时间达到 30 秒、总耗时达到 180 秒时为 0 分；中间区间线性递减。分数是阈值映射，不是可用性概率。

稳定性对至少有两个有效值的成功延迟维度计算：

```text
维度波动分 = 100 / (1 + 标准差 / 均值)
连续失败系数 = 1 - max(0, 最长连续失败次数 - 1) / (有效尝试数 - 1)
稳定性分 = 可用延迟维度波动分的平均值 × 连续失败系数
```

实现使用该组观测值的总体标准差。没有观测的时间空档不是失败。连续失败只按相邻的有效尝试判断；进行中的尝试会中断当前连续失败段。没有可计算的延迟波动分、且至少两次已完成尝试全部失败时，稳定性为 0；不足以计算稳定性时该项未知。

四项中任一项未知时综合评分显示 `--`，不把缺项当零分，也不把其余因素重新加权。少于 10 次有效尝试时仍显示可计算的分数，但标记低置信度。显示的综合分四舍五入为整数；颜色为 85 分及以上绿色、70–84 分黄色、低于 70 分红色。

此综合分不同于延迟泳道中的时间桶、P50 / P95，也不同于自动优先级使用的独立排序逻辑。缓存字段与成功尝试结果取决于上游支持和同步状态；比较平台前应确认统计窗口、样本数与字段完整性。
