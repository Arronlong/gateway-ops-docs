# 缓存指标与账号健康评分

v1.1.2 起，渠道和 Sub2API 中转站账号的近期环形指标保留缓存命中与 TPS，移除重试感知成功率环形及其排序入口。综合健康评分改为稳定性、缓存命中、延迟三项各占 1/3，不再使用成功 / 重试结果或连续失败系数；历史最终成功率、调用状态和原始错误仍有各自用途。

公开分组也使用缓存与 TPS 两项环形展示，但由后台快照聚合，不能直接套用账号前端计算流程。采样、完整性和最终成功率见 [公开页面的数据规则](/logic/public-monitor-and-pricing)。

## 统计窗口与有效样本

统计时长可设为 1–24 小时，默认 1 小时；最近数量为 1–200 的整数，默认 60。以当前时刻前 45 秒为截止点，回看所设时长，再按时间倒序取最多所设数量；两项同时限制选样，缺少记录不补成零。

健康评分再从选中样本排除进行中、辅助、探测与已确认的 cyber 请求；被排除后不另补更早请求。有效耗时必须是有限正数。稳定性和延迟直接读取实测首字 / 总耗时，不要求先判定请求成功，也不因成功标志、HTTP 状态或重试结果改变评分。

修改参数后点击“监控指标”标题行的“保存监控设置”。配置存于 PostgreSQL，影响近期指标、综合评分、相关排序及样本读取数量，不改变后台采集周期、历史保留、预警窗口或自动优先级。分组快照会在后续后台计算后采用新参数，页面刷新只读取已有结果。

## 缓存命中率

```text
缓存命中率 = 缓存读取 Token 数
           / (输入 Token 数 + 缓存读取 Token 数 + 缓存创建 Token 数)
           × 100%
```

缓存创建量优先使用汇总字段，未提供时使用 5 分钟与 1 小时缓存创建量之和。窗口内按 Token 总量加权，不是逐请求命中率的平均，也不是命中请求数除以总请求数。普通输入仍计入分母；无有效 Token 总量时未知，不能当作 0% 或 100%。健康评分的缓存项使用上述健康样本过滤后的集合，独立缓存环形与评分的有效样本集合可能不同。

## TPS 输出速度与独立评分

TPS（每秒输出 Token 数）显示在渠道与中转站账号的近期环形指标中。先按本页统计窗口和最近数量选样本，再在已选集合中筛选有效计量；排除记录后不会另补更早的调用。

```text
TPS = 有效样本输出 Token 总数 / 有效样本请求总耗时（秒）
TPS 评分 = min(100, TPS × 2)
```

例如两个有效请求分别输出 40 / 90 Token、耗时 2 / 3 秒，TPS 为 `(40 + 90) / (2 + 3) = 26`，评分为 52。分母包含请求总耗时，不减去首字等待时间；既不是各次 TPS 的简单平均，也不是观察窗口的墙钟吞吐量。

| 样本情形 | 处理规则 |
| --- | --- |
| 辅助、探测或已确认的 cyber 调用 | 使用现有分类与标记排除。 |
| 进行中请求 | `in_progress` 或 `attempt_status` 为进行中时排除，避免未完成耗时进入分母。 |
| 图片请求 | 请求类型含 `image`，或模型名命中已有图片模型识别规则时排除，包括渠道仅返回模型名的图片补计量。 |
| 输出 Token | 必须为有限非负数；零值或省略的零值按 0 计入，仍保留该请求有效耗时，不借此抬高速度。 |
| 总耗时 | 必须为有限正数；缺失、0、负数或无效数不参与。 |
| 请求结果 | 不额外要求 HTTP 成功；已经结束且满足以上条件的尝试仍按实际输出与耗时计算，不等同于成功率。 |

环形中心显示原始 TPS（Token/s），环形进度与列表的“TPS 评分”使用上述封顶分值：0 TPS 为 0 分，25 TPS 为 50 分，50 TPS 及以上均为 100 分。因此选择该排序时，高于 50 TPS 的项目不会继续按原始速度拉开评分。没有有效计量时显示 `—` / 不可用；有有效耗时但输出全为零时是 0 TPS，不是未知。

悬停可查看参与模型、统计时长、数量上限、输出总量、总耗时及评分过程。多个模型可能合并在同一环形指标中，应结合模型清单判断，不能把它当成同模型的标准性能测试。TPS 有效计量数也可能少于窗口内选中样本数。

TPS 仅作为独立指标与排序依据，不加入三项综合评分，也不改变后台自动优先级。时间桶的输出速度 P50 / P95 先计算每条速度再求百分位，不能用本页聚合 TPS 代替，见 [延迟与稳定性](/logic/latency-and-stability)。

## 三项综合评分

```text
综合评分 = round((稳定性分 + 缓存命中分 + 延迟分) / 3)
```

| 因素 | 计算说明 |
| --- | --- |
| 稳定性 | 对有效首字时间和总耗时分别计算 `100 / (1 + 标准差 / 均值)`，取可计算维度的平均值。每个维度至少需要两个有效值。 |
| 缓存命中 | 过滤后的健康样本按 Token 总量加权，比例乘 100 转为百分制。 |
| 延迟 | 每条记录对可用的首字分和总耗时分取平均，再对有效记录平均；不按请求结果过滤。 |

首字时间在 10 秒内、总耗时在 60 秒内为 100 分；首字达到 30 秒、总耗时达到 180 秒时为 0 分，中间线性递减。稳定性使用总体标准差；没有采样的时间空档不当作失败，已移除连续失败系数和“全失败自动为零”的评分分支。

任一项未知时，总分显示 `--`，不补零、不重分配其他项权重。有效首字或总耗时样本少于 10 条时标记低置信度，计数不再使用成功尝试数。分数四舍五入到整数，85 分及以上绿色、70–84 黄色、低于 70 红色。

本分数与时间桶的 P50 / P95、最终请求成功率和自动优先级是不同指标。移除重试感知成功率的展示不删除历史结果，也不表示系统停止读取上游错误；比较前仍需核对时间窗口、样本量、模型和字段完整性。
