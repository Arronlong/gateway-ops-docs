# New API 中转站管理规则

GatewayOps v1.0.2 支持将 New API 作为中转站接入。平台适配器把 New API 渠道、分组、用户和日志映射到统一界面；这不代表两类平台的字段和管理能力相同。

## 添加站点与凭据

在中转站管理中选择“NewAPI”，填写名称、基础地址和一种管理员凭据：

| 方式 | 必填内容 | 说明 |
| --- | --- | --- |
| 用户名 / 密码 | 管理员用户名、密码 | 登录账号须具备管理员角色。要求二次验证时，改用已验证的令牌或 Cookie。 |
| 访问令牌 | 管理员令牌、管理员用户 ID | 用户 ID 必须是正整数，并与令牌身份一致。 |
| Cookie | 管理员 Cookie、管理员用户 ID | 使用已完成登录及验证的管理员会话。 |

管理凭据在数据库中加密保存。管理请求必须使用 HTTPS；只有 `localhost`、`127.0.0.1` 和 `::1` 允许开发用途 HTTP。不要把密码、令牌或 Cookie 放入公开配置和日志。

可选“网关 API Key”不同于管理员凭据：读取管理员可访问的渠道模型不需要它；真实分组调用测试时，显式指定的 Key 必须归当前管理员所有且属于目标分组。未指定时系统尝试选择匹配令牌。

编辑时，同一鉴权模式下秘密字段留空表示保留旧值。切换鉴权模式需填写新模式凭据。

## 首次配置

1. 确认管理员有读取渠道、用户和用量日志的权限；修改分组倍率需要 root 权限。
2. 添加 New API 站点，测试连接并完成快照同步。
3. 检查渠道、分组、用户和用量是否齐全。
4. 通过明确的渠道关联或手工覆盖配置账号成本；New API 不支持 Sub2API API Key 成本探测。
5. 再配置调度、优先级、模型类型和自动策略，规则见 [自动调组](/logic/auto-group-adjustment) 与 [自动优先级](/logic/auto-priority)。

## 对象映射与能力边界

| 统一界面 | New API 来源与规则 |
| --- | --- |
| 中转站账号 | 映射 New API 渠道；状态用于调度，名称、模型和令牌配置用于展示及操作。 |
| 分组 | 映射 New API 分组名并生成稳定本地 ID；改名需先在远端完成，再重新同步。 |
| 分组模型 | 从管理员可访问的启用渠道配置读取，不要求 Gateway API Key。 |
| 分组倍率 | 读写全局分组倍率配置；修改需要全局设置权限，通常为 root。 |
| 用户余额与消费 | 按 `quota_per_unit` 换算，不要把原始 quota 当货币值。 |
| 用量记录 | 从成功及错误日志映射请求、Token、用户扣费和上游提供的延迟。 |
| 优先级 | 统一界面数值越小优先级越高；适配器会转换 New API 原生排序语义。 |
| 成本探测 | 不支持 Sub2API API Key 倍率探测；未知成本不等于零成本。 |
| 并发、池重试 | 上游无对应 Sub2API 语义，不显示或不可用。 |
| 用户并发与 RPM | 不支持批量配置。 |

渠道启停、调度、优先级、映射的分组配置及用户状态等有实现映射的操作会写入 New API。没有原生能力的字段会明确报错。批量操作可能部分成功，完成后检查结果并重新同步。

## 用量与完整性

报表读取成功和失败日志的原生分页，用户统计复用同一短时快照。首次完整读取大量日志可能较慢；报表缓存约 1 分钟。

用户与日志 quota 按 `quota_per_unit` 换算；当上游未提供正的换算值时，适配器使用 `500000`。成本结合日志中可用的倍率字段映射；缺少有效成本信息时，不能认为成本完整。New API 缺并发字段时显示能力差异，而不是 0。

同步成功不代表每个字段齐全。管理员日志权限、筛选窗口、远端分页和字段差异均影响完整性。

## 旧站点升级

旧中转站的 `type` 默认迁移为 `sub2api`，不会自动改变现有站点类型。新增 New API 站点时明确选择类型并填写相应凭据。
