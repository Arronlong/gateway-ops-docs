# 渠道与中转站调用对比

渠道记录反映上游站点的调用情况，中转站记录反映 Sub2API 账号的调用情况。页面按账号关联将两侧数据并排展示，帮助观察首字时间、总耗时和输出速度差异。近期调用配对依赖模型、Token 数和时间等条件，需要结合原始记录判断是否属于同一次请求。

## 如何查看

1. 确认渠道凭据账号与目标中转站账号已有有效关联，再检查两侧同步时间。
2. 在渠道管理的“最近调用”中悬停一条记录，查看当前渠道与关联中转站账号的首字时间、总耗时和 Token 速度。
3. 在中转站账号的“最近调用”中悬停一条记录，反向查看已关联渠道的数据；同一渠道会合并展示其关联账号信息。
4. 在“时间稳定性”中悬停非空时间桶，查看请求数、成功率、延迟和输出速度 P50 / P95，并对照关联侧的时间桶。
5. 点击近期调用或非空时间桶，打开调用明细。点击近期调用时，若有对应时间桶，打开的是该桶的明细；没有对应桶时只展示当前记录。

当前后台时间桶明细默认最多读取最近 30 条。标题中的请求数是该桶的统计总数，不能用明细列表条数代替。明细包含时间、模型、已知请求结果、首字时间和总耗时，后台弹窗还会展示可用的请求类型、用户邮箱、输出速度及 Token 总数。

## 关联范围

仅已命中且远端账号 ID 有效的关联参与对比。中转站账号使用“站点 ID + 远端账号 ID”定位，不同站点出现相同账号 ID 时仍是不同对象。

渠道侧按调用记录携带的渠道账号 ID 选择对应关联和采样；中转站侧只使用关联所包含的渠道凭据账号记录。同一渠道下其他账号的请求不会因为共用站点地址就自动成为当前记录的候选。

这些关联用于选择比较对象，不会创建调用记录、执行性能测试或直接修改成本倍率。成本归属与覆盖规则另见 [成本与倍率](/logic/cost-accounting)。

## 近期调用怎样配对

配对使用已读取的近期样本，页面通常读取最多 60 条，具体条带可能展示更少。它不遍历全部历史，也不要求两侧列表长度相同。

先筛选与当前记录时间相差不超过 10 分钟，且满足以下至少一项的候选：

- 模型相同：去掉首尾空白并忽略大小写，当前模型必须非空。
- Token 总数相同：按可用字段相加，总数必须大于 0。

Token 总数按实现中的输入、输出、缓存读取、缓存创建、5 分钟缓存创建和 1 小时缓存创建字段相加；缺失字段按 0 处理。上游拆分或合并缓存字段的方式可能不同，这个值不能当作统一计费口径。

候选排序依次优先模型相同、Token 总数相同、时间最接近。例如，同模型且相差 4 分钟的记录，会排在只有 Token 总数相同但相差 1 秒的记录之前。

没有上述候选时，两侧按时间从早到晚排序，用当前记录在主侧列表的相对位置映射到另一侧列表，并四舍五入到最近索引。主侧记录无法定位，或任一侧仅有一条时，回退为另一侧的最新记录；另一侧完全没有样本时返回未匹配。

位置回退没有 10 分钟距离限制，多条记录也可能选中同一条对侧记录。因此，页面显示关联数据不等于完成了一对一的请求追踪；对账或定位具体失败时，应核对两侧原始日志。

## 时间桶怎样对齐

两侧窗口请求的读取时间可能不同，桶开始时间不一定完全相同。选择对侧桶按以下顺序进行：

1. 开始时间完全相同。
2. 对侧桶的 `[开始, 结束)` 区间包含当前桶开始时间。
3. 选择开始时间最接近的对侧桶。

没有指定目标开始时间时，选择最后一个有请求的桶；全部为空时使用最后一个桶。最近开始时间的回退没有最大距离约束，排查时需检查时间范围和粒度，不能只凭并排显示就认为两桶覆盖完全相同。

## 速度、空值与数据新鲜度

单条输出速度为 `输出 Token 数 × 1000 / 总耗时毫秒`，单位 tokens/s。桶速度 P50 / P95 先算每条有效请求的速度，再计算百分位；总耗时包含首字等待时间。详见 [延迟与稳定性](/logic/latency-and-stability)。

没有输出 Token、总耗时无有效正值、未提供成功状态或没有采样，应分别理解为缺少对应字段或记录，不能替换为 0、0% 或已失败。桶请求数为 0 时按无调用理解。

对比读取已同步的历史样本。刷新页面或悬停只查询数据，不会立即向上游发起真实请求。出现两侧记录不一致时，先检查账号关联、同步错误、所选范围、样本保留和上游字段，再决定是否执行完整同步。
