# 自动优先级与召回

自动优先级在中转站快照同步后，把 OAuth 账号设为 `1`，把 API Key 账号按近期延迟映射到 `2–10`。该策略与页面的 0–100 时间稳定性评分使用不同算法。

## 配置与触发

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `auto_priority_enabled` | `false` | 必须开启，才会写远端优先级。 |
| `auto_priority_recall_enabled` | `false` | 在自动优先级开启时，允许召回长时间未使用的 API Key 账号。 |
| `auto_priority_recall_minutes` | `180` | 召回等待时间，保存范围为 `15–10080` 分钟。 |

完成快照保存和自动调组后才进入这一阶段。当前值与目标值相同时不写远端。手动设置优先级后，下一次触发已开启的自动策略可能重新覆盖该值。

## 延迟排序公式

对账号当前保存的近期样本求平均：

```text
延迟排序分 = 平均（首字时间毫秒 / 10000 + 总耗时毫秒 / 60000）
```

分数越小，目标优先级数字越小。样本来自近期最多 60 条保存记录，既不是所选 7 天 / 30 天窗口的全部请求，也不按样本年龄衰减；读取失败时可能继续使用以前保存的样本。

排序相同分数使用同一档，同分比较容差为 `1e-9`；排序过程中同分按远端账号 ID 排列。设不同分数共有 `n` 档，当前档从 `r = 0` 开始：

```text
n <= 1 时：目标优先级 = 2
n > 1 时：目标优先级 = 2 + 四舍五入（8 × r / (n - 1)）
```

| 账号情况 | 目标优先级 |
| --- | --- |
| OAuth | `1`，不使用延迟排序。 |
| API Key 没有可解析的样本 | `2`。 |
| API Key 只有一种不同延迟分数 | 全部为 `2`。 |
| API Key 有 3 种不同延迟分数 | 从低到高分别为 `2`、`6`、`10`。 |
| 其他账号类型 | 此策略不自动设置。 |

无样本被赋为 `2` 是当前实现的默认策略，不表示它比已有样本的账号更健康。基础排序没有额外按启用或可调度状态排除账号；调整优先级本身不会重新开启调度。

## 召回如何覆盖基础目标

召回只针对当前可调度的 API Key 账号。没有最近使用时间，或最近使用时间严格早于“当前时刻减等待时间”时，目标优先级改为：

```text
召回目标 = max(2, 当前优先级 - 1)
```

这是每次快照同步推进一级。例如账号当前为 `8`，已超过 180 分钟未使用，后续连续同步会依次变成 `7`、`6`、`5`，最低到 `2`；不要求每推进一级重新等待 180 分钟。

若当前手动优先级高于 10，召回仍从当前值每轮减 1，期间可能高于基础排序的 2–10 范围；它不会先强制降到 10。再次被使用后，下一轮同步恢复按延迟计算的基础目标。召回不调整 OAuth、不改并发、不改可调度开关，也不执行真实请求来制造使用记录。

## 排查顺序

先确认自动优先级开关及快照任务是否开启，再看样本时间与最近使用时间。最后检查是否先前的自动调组报错，导致优先级阶段未执行。页面评分的规则见 [延迟与稳定性](/logic/latency-and-stability)。
