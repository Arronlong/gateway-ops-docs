# 自动调组

自动调组在中转站快照同步后比较账号成本倍率与销售分组倍率，移除亏损或无利润组，并在需要时加入可盈利候选组。它会修改 Sub2API 的账号分组；请先确认成本来源和账号模型类型。

## 开关与触发时机

| 配置 | 默认值 | 行为 |
| --- | --- | --- |
| 亏损自动调组 `auto_adjust_enabled` | `false` | 处理亏损；没有安全候选时可关闭账号调度。 |
| 无利润自动调组 `auto_adjust_no_profit_enabled` | `false` | 处理成本与销售倍率相等的账号。 |
| 账号模型类型 | 未绑定时为空 | 自动调组必须先绑定；为空则整条账号跳过，包括自动关闭调度。 |

一次快照同步先保存账号、分组与关联快照，再协调渠道关联，随后执行自动调组，最后执行自动优先级。手动快照同步也会触发已开启的策略。中转站倍率同步成功保存成本并协调关联后，也会执行已开启的自动调组；单账号探测、打开页面或刷新页面不直接触发调组。倍率同步不执行自动优先级。

自动调组阶段报错时，本轮后续自动优先级不会执行；已成功写入的快照和账号变更可能仍然保留。查看同步错误和调整记录，不能把整轮同步理解为一次原子事务。

## 成本与当前组如何判断

成本使用 [成本与倍率](/logic/cost-accounting) 中的有效成本来源。没有有效成本时为“成本未知”，不参与自动调组。非 `active` 账号也不继续计算调组风险。

只把启用、平台匹配且账号类型兼容的当前销售组用于比较。平台忽略大小写及两侧空格。系统分别识别：

- 分组倍率小于成本：亏损组。
- 分组倍率与成本相等：无利润组，浮点比较容差为 `1e-9`。
- 分组倍率大于成本：盈利组。

只要有亏损组，风险状态优先按亏损处理；没有亏损但有相等组时为无利润。没有有效当前组时为未分配，不会因此自动补组。

## 候选组必须满足什么条件

1. 分组状态为 `active`，平台与账号一致。
2. 分组倍率严格高于成本，只有相等倍率不够。
3. 账号类型兼容：要求 OAuth 的组排除 API Key；已有账号类型记录的组要求类型属于该集合；空组没有这项历史类型限制。
4. 自动调组额外检查模型类型：分组配置模型类型列表时，账号绑定的模型类型必须在其中；分组模型类型列表为空时接受任意已绑定的模型类型。

候选按倍率升序排列，同倍率按远端分组 ID 升序。系统选择最低倍率的盈利候选，不按请求速度或“最高利润”选择。

## 最终如何改组

系统保留原有不需要移除的组，去掉亏损和无利润组。如果剩余组中已有有效盈利组，就不额外添加推荐组；否则添加排序第一的盈利候选。最终组列表没有变化时不写远端。

| 当前情况 | 配置与结果 |
| --- | --- |
| 有亏损组且有可用建议 | 开启亏损自动调组后应用建议。 |
| 只有无利润组且有可用建议 | 开启无利润自动调组后应用建议。 |
| 有亏损组但没有安全候选 | 开启亏损自动调组、账号已绑定模型且当前可调度时，关闭调度。 |
| 只有无利润组、没有可用建议 | 不执行自动关闭调度。 |
| 成本未知、账号未启用、模型未绑定或未分配有效组 | 跳过相应自动调整。 |

自动策略没有对应的自动恢复调度步骤。修正倍率或候选组后，仍需检查账号的可调度开关。

## 示例

账号成本为 `0.8`，当前组倍率为 `0.6` 和 `1.2`。移除 `0.6` 后已经有盈利组 `1.2`，因此保留 `1.2`，不再为了降低倍率而自动加入 `0.9`。

若当前只有 `0.6`，符合平台、账号类型和模型条件的候选为 `0.8`、`0.9`、`1.2`，则选择 `0.9`。`0.8` 与成本相等，不是盈利候选。

## 手动操作的差别

普通手动调组建议使用基本盈利条件，不完全等同于自动调组的模型限制。“可降级分组”要求账号模型已绑定、模型类型兼容，并满足 `成本 < 候选倍率 < 当前最低有效倍率`。批量追加可降级分组会保留已有组，不替换全部组。

每个成功修改的账号分别更新远端及本地关联，并写调整记录。批量操作允许部分成功；处理失败项前先确认成功账号的最终分组。操作入口见 [中转站管理](/guide/relay-stations)。
