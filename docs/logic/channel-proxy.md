# 渠道代理与请求出口

v1.1.2 起，可在渠道新增 / 编辑表单选择 HTTP / HTTPS 代理。代理记录全局复用，每个渠道单独绑定，不会把所有中转站或所有请求统一切换到同一出口。

## 添加与使用

1. 打开渠道编辑的“代理”，选择已有脱敏地址，或点击“新增代理”。
2. 输入完整 URL，例如 `http://user:password@proxy.example.com:7890`，点击“添加并选用”。
3. 保存渠道，再用现有登录测试 / 同步检查目标站点连通性和认证。新增代理本身不代表已通过连接测试。
4. 其他渠道可复用同一条记录；选择“不使用代理”并保存，解除该渠道的显式代理绑定。

新增代理与保存渠道是两个动作：新增会先持久化全局代理记录，渠道保存后才更新绑定。相同规范化完整 URL 按哈希复用记录；不同账号密码代表不同 URL，不会因脱敏外观相同而混用。URL 最长 4096 字节，允许有效端口 1–65535；仅支持 `http://`、`https://`，不接受 SOCKS、缺少协议、业务路径、查询参数或片段。

## 出口适用范围

| 请求 | 行为 |
| --- | --- |
| 渠道登录、会话校验、余额 / 倍率 / 使用记录采集及历史回补 | 继承该渠道保存的代理，凭据账号沿用父渠道出口。 |
| 支持的渠道 Token 刷新 | 使用所选渠道代理；任务范围和刷新权限不因代理扩大。 |
| 渠道测智、关联账号测智中的渠道目标请求 | 明确选择的渠道代理优先于目标原有代理，并隔离传输层，不改共享客户端。 |
| 测智 Key 分组信息查询 | 按被查询会话所属渠道出口处理，不串用另一渠道的固定代理。 |
| 未绑定渠道代理的请求 | 沿用原传输行为；默认 HTTP 传输仍可能读取服务器的 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`。 |

界面的“不使用代理”表示没有显式绑定渠道代理，不承诺强制绕过服务器环境代理。它不改变中转站独立管理接口或分组网关的既有网络配置，也不会自动调整所有上游账号的代理。

## 凭据与网络边界

完整代理 URL 使用 `APP_SECRET` 加密保存在 PostgreSQL。接口返回 ID、脱敏 `display_url` 和时间等信息，不返回密文或明文密码；URL 中的密码被遮蔽，用户名和主机仍可见。请求错误会处理可识别代理秘密，但共享日志前仍应检查内容。

更换部署或恢复备份时，保留原 `APP_SECRET`，否则保存的代理无法解密。选中不存在或无法解密的代理应先修正配置，不要把出口错误误判成余额为零、没有调用或 Key 无效。

代理地址由后端访问。Docker 中的 `127.0.0.1` 是应用容器自身；要访问宿主机或另一容器，应使用该部署可达的地址、网络和端口。代理支持 HTTPS 不等于允许跳过目标 TLS 验证。相关凭据与使用规则见 [渠道管理](/guide/channels)、[同步与数据处理](/logic/synchronization) 和 [安全与访问](/logic/security-and-access)。
