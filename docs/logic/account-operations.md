# 账号操作与测试

中转站账号操作会调用远端 Sub2API 管理接口，再同步本地状态。批量操作按账号处理，允许部分成功；执行后看结果明细，不应根据整批报错推断所有账号都未修改。

## 并发、优先级与同账号重试

| 配置 | 保存范围 | 当前行为 |
| --- | --- | --- |
| 并发数 | `1–1000` | 手动写远端运行配置，不由自动优先级推算。 |
| 优先级 | `1–1000` | 手动设置；已开启自动策略时，下次快照可能覆盖。 |
| 同账号重试次数 | `0–10` | 写入远端凭据的 `pool_mode` 及 `pool_mode_retry_count`。 |

一次更新至少填写一项。设置重试次数时同时启用 `pool_mode`；次数为 0 不表示删除所有池模式配置。它由 Sub2API 处理调用重试，与 [通知投递重试](/logic/notifications-and-captcha) 无关。

优先级变化会记调整日志；并发和重试为手动运行参数，当前并不因此各生成一条优先级调整日志。可调度开关与优先级数字独立，调整优先级不等于开启账号。

## 批量克隆

支持以 API Key、上游、Bedrock 和服务账号为源，影子账号需选择母账号；OAuth 不在当前允许克隆的类型列表中。源账号需要同时存在于本地快照和远端。

一次最多选择 100 个源账号，每个源账号最多新增 100 个，总新增最多 300 个；源账号不能重复选择。新账号 API Key 必填，名称最多 255 字符、模型类型最多 64 字符。

先在远端复制源账号，再更新新账号名称和凭据；填写 Base URL 时覆盖，未填时沿用复制得到的配置。新账号设置为 `active`、`schedulable=false`，需要检查配置后手动开放调度。模型类型绑定属于后续本地配置步骤。

复制成功而后续更新失败时，远端可能已经存在一个新账号；结果中的远端 ID 有助于查找。重试前先检查该对象，不能假设失败会自动删除刚复制的账号。

## 倍率探测

单账号上游倍率探测只支持 API Key 类型，调用 Sub2API 上游计费探测接口。批量探测以每批最多 20 个账号提交。

有效探测要求结果状态成功且提供非负的 `resolved_rate_multiplier`，观察时间来自探测数据。失败或没有有效成本时保留上一成功结果；上游账号默认倍率不能替代探测来源。该操作不等于一次模型推理性能测试。

## 账号真实请求测试

账号测试调用 Sub2API 账号测试接口，可提交所选 `model_id` 和 `mode`，并展示 HTTP 状态、耗时和上游输出。HTTP 成功只表示接口返回成功，具体测试模式结果还需看输出；所支持模式由部署的 Sub2API 决定。

测试可能产生上游用量，成本和延迟是否进入后续统计取决于远端记录及采集。不能把测试按钮当作只读取本地配置的操作。

## 分组真实请求测试

分组测试使用该分组有效的网关 API Key，先选择模型，再串行执行 `1–10` 次真实调用，分别统计成功和失败。管理员 API Key 与网关调用 Key 不同；缺少分组网关 Key 时无法测试或读取该分组模型目录。

上下文取消可能提前停止，实际返回结果数少于请求次数。测试后公开监控缓存会失效，但其他区间统计仍需等待远端记录和正常查询 / 同步。

分组测试用来观察该组实际路由表现；不同请求可能被 Sub2API 分配到不同账号，不能据此认定所有组内账号都已分别测试。
