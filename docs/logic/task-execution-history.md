# 定时任务执行历史

系统设置中的“执行记录”用于回答某个自动任务何时开始、是否结束、失败在哪里。记录保存在 PostgreSQL，不是浏览器临时日志，也不是上游完整请求审计。

## 从哪里查看

在渠道同步、渠道 Token 刷新、中转站倍率探测、快照同步及鹈鹕测智方案旁点击“执行记录”。系统设置还提供每日余额、历史清理和兼容任务的记录入口。

| 任务标识 | 含义 |
| --- | --- |
| `channel_sync` | 渠道余额、倍率与调用数据完整同步。 |
| `channel_token_refresh` | Sub2API Token 模式渠道主动续期。 |
| `relay_rate_sync` | 中转站 API Key 倍率探测。 |
| `relay_snapshot_sync` | 中转站快照同步及其后续步骤。 |
| `daily_balances` | 每日余额快照。 |
| `retention` | 已配置的业务历史清理。 |
| `pelican` | 鹈鹕定时调度检查，不等同于某份作品。 |
| `legacy_balance` / `legacy_rates` | 尚未切换为页面同步配置时的兼容余额 / 倍率扫描。 |

## 状态与日志

列表展示 `running`、`success` 或 `failed`，以及开始 / 结束时间、耗时、结果摘要；点击记录查看日志。列表每页 20 条，打开时约每 5 秒刷新；汇总数量覆盖该任务全部记录，不仅是当前页。

日志在任务完成时写回，运行中尚未有最终日志不等于没有工作。错误日志、执行返回错误、超时或 panic 会使该轮失败；部分对象已经成功处理时不会自动回滚。启动时会将此前未结束的运行记录标记为中断失败，因此服务重启后的失败记录不一定是业务接口返回失败。

没有到期对象、功能关闭或不在允许时段时，鹈鹕检查可能正常结束且未生成作品。查看日志中的跳过原因，再到作品详情核对每份结果；不能仅凭调度记录为成功判断模型生成成功。

日志会遮蔽识别到的认证头、Token、密码、Key 和 URL 凭据，正文约 64 KiB 后截断。脱敏不能替代秘密管理；共享日志前仍应检查内容。历史详情不是逐条实时流式输出，也不能替代服务器完整日志。

## 覆盖边界与保留

仅记录该功能上线后的自动调度，以及接入同一任务包装器的启动执行；不补造旧历史，手动业务同步 / 测试不保证出现在这里。同类任务因重叠被跳过时，也不一定新增一条记录。

任务记录不按监控日志、通知日志或余额快照的保留天数自动清理。没有记录时先核对任务是否配置、启用且确实触发，以及数据库写入是否正常，不要仅靠空列表判断系统未运行。

后台接口为 `GET /api/tasks/:task/runs` 和 `GET /api/tasks/:task/runs/:id`，开启后台认证时需要登录。列表分页 `page >= 1`、`page_size=1–100`，默认 20；未知任务或不存在的记录返回 404，非法分页返回 400。

同步生效、任务重叠及业务数据保留见 [同步与数据处理](/logic/synchronization)，测智来源与生成结果见 [鹈鹕测智与作品历史](/logic/pelican-testing)。

## 与预警动作记录的区别

v1.0.5 的预警事件与远端启停动作在预警中心查看，不自动等同于本页的任务执行记录。规则命中、动作成功及通知成功分别记录；预警采样周期也不沿用现有快照任务的执行结果。详见 [预警中心](/guide/alerts) 和 [预警判定与安全自动化](/logic/alerts-and-automation)。
