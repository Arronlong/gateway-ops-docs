# 同步与数据处理

GatewayOps 从渠道、Sub2API 和账本读取多类数据。同步任务、倍率探测和真实请求监控是不同工作流；刷新某个页面不一定会触发所有工作流。

## 渠道数据

渠道连接器访问 NewAPI 或 Sub2API，按渠道类型读取余额、分组倍率和支持的使用记录。后台默认余额监控每 15 分钟执行，倍率监控每 30 分钟执行；间隔可由配置调整。单个渠道可暂停监控，也可手动测试登录或触发同步。

同步失败会更新最近错误信息并可能触发登录失败或监控失败通知。连续失败时检查凭据有效性、代理连通性、验证码和上游接口变化。

## 中转站快照与倍率探测

- **快照同步：** 更新账号、分组、渠道、用户及关联关系的本地快照；不会执行倍率探测。
- **倍率探测：** 单独读取或测试倍率数据，更新成本分析所需的信息。
- **真实分组测试：** 会发起请求并可能消耗额度、写入使用与监控记录；它不是只读同步。

快照用于列表、风险分析和账号关联。快照过期或某次 API 部分失败时，列表数据可能暂时落后于远端状态。

## 成本和用量

中转站用量统计按远端账号读取用户扣费、请求与 Token 等字段，再根据 GatewayOps 中的成本来源计算账号调用成本。批量读取并发执行；若部分账号失败，系统保留成功账号结果并标记失败数量。短时缓存用于降低重复远端请求。

渠道与中转站用量关联优先考虑显式的渠道分组成本绑定；没有显式绑定时，系统尝试根据渠道 Base URL 唯一匹配账号。匹配不唯一或不完整时，应检查配置而不是将结果视为完整覆盖。

## 监控记录与公开页面

分组监控样本来自实际记录的请求结果。公开监控页面使用近期调用结果形成成功、失败、延迟和可用性趋势；它不会因页面打开而主动对所有上游模型进行完整探活。公开页面缓存和后台刷新会使展示值短暂滞后。

模型价格列表依据当前可用模型与有效定价规则生成。分组 API Key 缺失时，模型归属或价格内容可能不完整。

## 告警处理

余额不足、倍率变化、登录失败、验证码失败和监控失败由对应任务或操作产生事件，再按订阅规则筛选收件渠道。倍率变化可按最小变化幅度过滤和批量合并；低余额可设置冷却；投递失败按配置重试。重试只针对通知发送，不会自动重跑上游同步任务。

## 历史数据清理

示例配置默认每天清理 30 天前的监控日志、90 天前的余额快照和通知日志；倍率变化记录长期保留。部署者可修改保留期。调整之前应考虑趋势图和故障追溯所需的历史长度。
